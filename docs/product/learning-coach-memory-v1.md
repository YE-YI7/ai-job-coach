# 对话辅导与学习档案 · 2026-09-13

## 用户路径

中间只突出一项练习：当前材料暴露的问题 → 怎么练 → 开始对话辅导。进度与历史折叠。无简历/JD也能开始第一堂练习。已有成果的人仍能直接去材料工作台，不强制上课。

右侧：一轮示范 → 用户作答 → 针对回答反馈 → 重试/迁移题。支持独立辅导、历史找回、结束保存、失败保留输入与幂等重试。归档后中间推荐继续上次卡点。不是每条消息启动多Agent工作流。

## 记忆分配

| 内容 | 持久真源 | 本轮输入 |
| --- | --- | --- |
| 全局经历与背景 | 原始 sources/claims；`coach_memory_documents` 下 `profile/overview.md` | 摘要最多1800字符；相关事实经 Context Compiler 选择 |
| 当前学习 | `coach_learning_sessions` + `coach_agent_turns` | 最近4轮，各轮问题700/回答1000字符上限 |
| 学习进展 | 结束时写 session.summary；逻辑路径 `learning/<id>.md` | 最近3份同岗位/通用摘要，进入本轮最多1800字符 |
| 公共知识 | 26份受版本管理的知识文档，89条来源证据；编译JSON供网页和Plugin检索 | 每轮最多2份，包含正文、适用边界、来源；不是仅Description |

逻辑文件夹由数据库承载，不是假称已有容器文件系统。下载接口提供Markdown档案；原始材料不因压缩而删除。背景采用**抽取式 compaction**，按内容指纹复用，避免每条消息额外调用模型。学习结束才生成一次AI摘要，显式区分已验证与待验证，附系统摘录和原文ID。不会把练习写成工作经历。

新辅导没有旧聊天窗口内容，但会读取摘要。归档读取最近200轮，每轮按总预算节选；超长会话不是无损全量压缩，原文仍存数据库。界面历史当前最多显示200轮，档案下载默认最近3份相关笔记。

## Harness / 费用

- 每次对话：当前问题 + 最近用户追问做词项检索；显式换题不带旧主题。不另调用LLM规划器，也不做无限检索loop。
- Context Compiler按岗位、用户、事实状态选择内容。补上了知识正文渲染和正文计入预算的缺口。
- 最终模型输入（含system、背景、近期对话、知识）估算上限8000tokens，输出1200tokens。估算不是供应商计费数。
- 一轮一次模型调用；归档一次模型调用。自动进入新辅导前，若旧辅导有内容，先归档；界面明确这会用AI对话额度。不会自动充值。
- `learning_trace`记录prompt版本、所选知识ID、输入估算量、前轮ID和记忆加载状态，便于排查“检索到了却没用上”。不在公共日志输出用户原文。
- 知识当前采用轻量词项检索，不宣称向量RAG；新增多轮检索回归和正文入prompt测试。后续若真实bad case证实词项召回不足再换索引。

## 沙箱取舍与成本估算

不为每个用户常驻计算沙箱。存档需要持久存储，执行不可信代码/浏览器自动化才需要临时计算隔离；这轮没有启用新付费基础设施。

以Vercel iad1公开价、默认4GB为例，等效持续运行30天的内存成本：4×720×$0.0212≈$61.06/用户/月，另计CPU、网络，未扣套餐抵扣。实际单沙箱最多24小时，需要重建，不能当永久机器。仅每人每天运行20分钟，内存约$0.848/月，仍另计CPU。

若1000人每人10MB档案，共约10GB。Supabase Pro公开包含100GB文件存储，超额$0.0213/GB/月；10GB按超额单价等效$0.213/月，**这不是整站账单，也不是本轮Postgres文本表的报价**。实际Postgres磁盘、计算、备份、流量和模型另算。小规模先用现有数据库，正文增长后迁私有对象存储。

来源：[Vercel Sandbox定价](https://vercel.com/docs/sandbox/pricing)、[Supabase定价](https://supabase.com/pricing)，核验于2026-09-13。

## 安全

新表RLS启用，anon/authenticated撤销访问；现有自定义登录由服务端owner过滤，不套用不适配的auth.uid。会话ID/岗位ID校验；turn与session绑定同一owner，触发器阻止归档后回写和跨岗位写入。归档版本冲突返回409，不假报保存。缓存和档案不跨用户复用。Supabase advisor的“RLS无policy”是服务端专用表的预期信息项。

教学人工量表（每项0/1/2，不能用格式正则冒充）：
1. 推荐是否对应当前用户问题，而非泛化课程；
2. 是否给可立即作答的练习；
3. 是否引用并准确点评用户回答；
4. 追问是否延续/纠正前轮；
5. 是否把假设、示范、真实经历分开；
6. 新窗口是否从未解决处继续，避免重复介绍。

任一虚构用户经历/泄露/假报保存为硬失败。小样本模型探针曾出现“去掉功能”的过度简化判断法，不能视为教学内容已全面合格。后续应以真人独立完成迁移题、纠错率、再次打开后的重复解释次数做效果指标，不以模型说“已掌握”计完成。
