# ★ Trace 阅读器：调用链与单节点证据

## 本人反馈与范围

原话：“你这个 trace 面板 我一直想说 列得太不清楚了 这一块那一块的 跟列表格似的 能不能好好学学人家 trace 是怎么列的？”

目标是帮助本人顺着一次调用查清：经历了哪些节点、点选节点实际输入是什么、显式编辑判断是什么、交出了什么、哪一步有问题。仅改 Eval 展示，保留所有数据与原始记录；不修改 Memory/B05/编辑器/审稿/模型/计费/账号权限，不混备份恢复或其他包，不部署。

## 参考与落地

阅读并实际打开 [Langfuse 官方 Trace 重设计说明](https://langfuse.com/changelog/2025-03-19-new-trace-view)，参考其调用层级/时间线、单节点详情、搜索与可隐藏低频信息；另阅读 [LangSmith 官方 tracing quickstart](https://docs.langchain.com/langsmith/observability-quickstart) 对实际输入输出与嵌套调用记录的说明。没有接入这两个服务，也未向其上传私人 Trace。

现版问题是运行列表、知识条目、阶段列表、左右原始 JSON、自评和人工反馈同时争夺有限宽度；完整输入虽存在，却不容易读出原稿与补充事实的边界。

候选实现：

- 默认收起运行记录和评估表单；保留明确入口，不删除功能。
- 左侧是当前调用链，右侧只读一个节点；输出/输入/调用信息/原始记录就地切换，支持键盘。
- 编辑输出按显式主线、可展开取舍和实际成稿阅读；粗体安全渲染。没有额外请求总结或生成新的分析。
- 输入按消息角色与原稿/补充事实展示；系统指令、知识条目和合同按需展开，搜索命中自动展开。
- 本机全文搜索实际已采集 I/O，字面匹配、高亮、空态和“选中节点不在筛选结果中”提示。不请求搜索服务或模型。
- 调用成功与输出失败分开；异常定位也识别原质检显式失败，不能把完成状态当质量通过。
- 树只用真实 `parentId`；时间线只用完整已记录起点及耗时，没有则禁用。空白不归因为模型等待，不伪造父子或并行。
- 原始节点含未知字段仍可查看，导出协议不改；历史未采集 I/O 不补造。
