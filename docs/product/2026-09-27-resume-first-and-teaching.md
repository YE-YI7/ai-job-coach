# 简历优先找岗与主动带学

## 09-27 续轮：首批招聘源接线

新增 `POST /api/coach/jobs/discover` 和基础档案中的「按我的方向找岗位」。读取当前用户拥有的 preparation 档案，公共招聘板固定为 Meshy / Kong 的 Ashby 公开接口，不接受任意来源 URL。逐源最多 12 秒、4MB、禁止重定向；仅保留 isListed=true、同招聘板 HTTPS 链接与非空描述，URL 去重。共享公共结果缓存 1 小时；个人候选响应 private/no-store，不缓存简历。方向、城市、简历不发送给招聘来源。

这是有限覆盖的确定性初筛，不是全网 AI 搜岗：中英方向/城市映射先筛选，简历与描述共同关键词排序，最多五项，无匹配百分比；远程不等于全球可工作。每项显示来源与真实读取时间。两源都失败返回 502，一源失败明确提示不完整；没有职位不等于用户没有机会。用户点击后才复用模型岗位分析，并带入当前基础档案原文（修复原先固定取第一份档案的问题），不自动投递。

实测公开接口：Meshy 27 条、Kong 78 条；上海产品经理查询本次零结果，上海工程方向有五个候选。不得宣传覆盖国内主流招聘平台。来源契约见 https://developers.ashbyhq.com/docs/public-job-posting-api ：公开招聘板查询并非全网接口，后续商业化扩源需逐源复核再分发政策。本次仅限登录用户按需筛选，不建公开镜像站。

验证：92 套 / 789 项测试、tsc、生产构建通过；新增 14 项覆盖用户隔离、无简历外发、部分/全量来源失败、非公开条目、外站链接、城市/岗位过滤。浏览器检查基础档案入口与 390px 布局，匿名查找提示登录。真实账号选岗→模型分析→云端保存仍未完成端到端签收。公司 Logo 批量映射、全网检索与定时主动找岗本轮未实现。Impeccable 只在收尾扫描一次；既有侧边色条/Georgia 警告保留，不扩大任务。

## 产品决策

不新增「掰岗位 / 掰简历」两套入口。一个个人工作区，一份基础简历，多份岗位版本。首次默认「导入简历 → 确认方向 → 推荐岗位 → 选岗推进」；已有 JD 的人仍可直接贴 JD，在确实需要判断匹配时再补简历。已经面试、谈薪的用户直接进入对应阶段，不重走新手路线。

导入后只请用户确认识别出的方向、城市、年限，采用可修改选项，不再填整套问卷。首次展示 3–5 个可追溯岗位，每项写清推荐依据、主要缺口、来源和核验时间。避免凭模型印象给匹配百分比。选中后进入现有阶段轴。没有简历的人可以从经历梳理或第一项练习开始。

教学不另开工具首页：在当前任务遇到困难时，导师接住困难、解释一个概念、给一个例子、让用户试一次、反馈后重答。练习完成不等于真实工作经历，也不能自动增加能力事实。

## 公司 Logo

可以实现：建立公司实体与已核验官网域名的映射，使用允许展示的官方品牌资源并缓存。记录来源；公司别名、同名企业需消歧。没有可靠图片就显示公司首字，不伪造 Logo、不将任意站点 favicon 当作已核验品牌。属于后续找岗数据接入，本轮没有声称已经覆盖公司库。

## 岗位数据技术路径

1. 首批面向 AI 产品岗位选择企业招聘官网白名单；先确定国内覆盖，再扩展海外 ATS，不能用海外接口数量冒充国内覆盖。
2. 优先公开招聘接口或获得授权的数据源。Greenhouse Job Board 的读取接口与 Ashby 公共 Job Postings API 可按企业招聘板获取岗位，不是全网职位搜索接口。公开可读不自动等于无限再分发授权，接入时逐源核对使用政策。
3. 搜索引擎只负责发现官网详情链接；可访问且允许采集的页面再结构化。LinkedIn 等登录平台不走借用用户 Cookie、验证码绕过或批量爬取路径。保留用户主动粘贴 JD 作为覆盖不足时的入口。
4. 保存 canonical URL、公司、原始职位 ID、标题、地区、描述、发布时间、抓取时间、来源及有效状态。按 URL/职位 ID 去重、内容哈希识别变更。只展示可公开列出的岗位；下架与长期未核验明确标记，发布日期早不能单独等同于失效。
5. 采集在共享后台缓存完成，不给每个用户重复爬。初始刷新间隔 6–24 小时按来源调整；遇到限流退避，遇到登录/验证码停止。规则先过滤地点/级别等硬条件，再让模型对少量候选解释推荐理由。
6. 外部检索仅携带去标识化技能与求职偏好，不发送整份简历和联系方式。抓取服务须限制域名、重定向、响应大小，防 SSRF；网页文字按不可信材料处理，清洗 HTML，不能把页面指令升级为工具权限。

## 主动导师的边界与成本

- 用户明确说「教我」「不会答」：立即将当前题目和原话交给右侧导师，单次请求直接带学，不先运行一次评分再额外跑教学。新辅导保留旧会话，不沿用不相关问题。
- 仅从点评推断出缺口：先给一条带题目的邀请，可稍后处理；不每次刷新都自动计费发言。
- 事件需带岗位与唯一事件 ID，防串岗、防重复；忙时等待，失败显示可重试，不伪造导师已回复。
- 本次上下文保留当前题目、尝试与必要历史；学习结束经用户确认的关键进展写入已有记忆/笔记。未经证明的技能不进入履历事实。
- 验收重心：用户能否完成一次实际尝试并改进，而不是打开过某个功能。评估求教识别误触发、题目/岗位绑定、回复是否循序带学、事实编造率与每次教学成本。

## 续轮实施：基础档案与点评后带练

已实施：空工作区主入口改为导入简历；保留有 JD / 直接面试的旁路。常驻「我的简历与方向」复用 preparation 云端档案，不新增不互通的表。基础档案不再显示岗位时间线或重复出现在岗位列表；旧的多份基础档案仍可打开。方向与城市可修改，云端确认成功才显示保存成功。新岗位带入基础简历原文，后端不采用模型改写来覆盖它；已有岗位定制稿不覆盖。更新基础简历按替换而非拼接处理。

单题点评保存后，基于该条反馈的第一项缺口，在右侧展示免费、可稍后的带练邀请；手机打开导师区。点击带练才调用既有带学通道，携带原题、原答及作为待核实参考的点评，不默认把点评当事实。明确求教仍直接进入教学。全局导师提示增加「解释→例子→试答→具体反馈→重答」约束；三轮以后在回答下提供整理进展入口，复用已有持久化归档与下次读取机制。不是后台无限自动发消息，不按渲染重复调用模型。

验证：90 套 / 775 项单元与路由测试通过，新增基础简历原文不可被模型改写和带练邀请绑定用例；类型检查通过。浏览器预览实测方向保存、进入已有岗位且定制稿不变、点评后对应邀请出现；390px 下邀请可见。预览反馈明确为演示数据，不作为真实模型或持久化验收。真实登录模型→练习→归档回读仍待验证；自动搜岗与公司 Logo 数据库未实现。生产部署以本轮发布记录为准。
