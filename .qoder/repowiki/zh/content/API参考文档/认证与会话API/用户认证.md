## 简介
本文档详细说明了AI求职教练项目的用户认证系统，重点涵盖会话创建和身份验证两个核心接口。系统采用基于邀请码的认证机制，通过Supabase作为后端身份验证服务，实现了安全的用户会话管理和身份验证流程。认证系统包含服务器端API接口、中间件拦截、客户端React Hook等多个组件，共同构建了一个完整的认证解决方案。

## 详细组件分析

### 会话创建接口分析
`/api/auth/create-session`接口是用户认证流程的核心，负责处理邀请码验证并创建用户会话。该接口首先验证请求体中的邀请码，然后通过Supabase Admin API检查或创建用户，最后生成会话令牌并设置Cookie。

```mermaid
flowchart TD
Start([开始]) --> ValidateInput["验证输入参数"]
ValidateInput --> InputValid{"输入有效?"}
InputValid --> |否| ReturnError["返回400错误"]
InputValid --> |是| CheckInvite["查询邀请码"]
CheckInvite --> InviteExists{"邀请码存在?"}
InviteExists --> |否| ReturnInvalid["返回邀请码不存在"]
InviteExists --> |是| CheckUsed["检查是否已使用"]
CheckUsed --> |已使用| UseExistingUser["使用现有用户ID"]
CheckUsed --> |未使用| CreateUser["创建新用户"]
CreateUser --> UpdateInvite["更新邀请码使用记录"]
UpdateInvite --> CreateSession["生成会话令牌"]
CreateSession --> SetCookie["设置会话Cookie"]
SetCookie --> ReturnSuccess["返回成功响应"]
ReturnError --> End([结束])
ReturnInvalid --> End
ReturnSuccess --> End
```

### 身份验证接口分析
`/api/verify`接口用于验证用户提交的验证码，是短信验证流程的一部分。该接口检查请求中的手机号和验证码，与缓存中的验证码进行比对，验证通过后清除缓存中的验证码。

```mermaid

CheckInput --> InputValid{"参数完整?"}
InputValid --> |否| Return400["返回400错误"]
InputValid --> |是| GetCached["获取缓存验证码"]
GetCached --> CodeExists{"验证码存在?"}
CodeExists --> |否| ReturnInvalid["返回验证码错误"]
CodeExists --> |是| CompareCode["比对验证码"]
CompareCode --> CodeMatch{"验证码匹配?"}
CodeMatch --> |否| ReturnInvalid
CodeMatch --> |是| ClearCache["清除缓存验证码"]
ClearCache --> ReturnSuccess["返回验证成功"]
Return400 --> End([结束])
```

### 客户端认证Hook分析
`lib/useAuth.ts`文件实现了客户端认证检查Hook，作为中间件的补充，确保前端组件也能正确处理认证状态。该Hook在组件挂载时检查会话状态，并定期验证会话有效性。

```mermaid
flowchart TD

CheckAuth --> HasSession{"有会话Cookie?"}
HasSession --> |是| CheckLocalStorage["检查localStorage"]
HasSession --> |否| CheckLocalStorage
CheckLocalStorage --> HasData{"有sessionId或inviteCode?"}
HasData --> |是| StartInterval["启动定期检查"]
HasData --> |否| RedirectLogin["重定向到登录页"]
StartInterval --> Interval["每30秒检查一次"]
Interval --> CheckAgain["重新检查认证状态"]
CheckAgain --> StillValid{"会话仍有效?"}
StillValid --> |是| ContinueInterval["继续检查"]
StillValid --> |否| ClearInterval["清除定时器"]
ClearInterval --> RedirectLogin
RedirectLogin --> End([结束])
ContinueInterval --> Interval
```

## 性能考虑
认证系统的性能主要受网络延迟、数据库查询效率和加密操作的影响。系统通过合理的缓存策略和异步处理来优化性能，确保用户能够快速完成认证流程。

- 会话有效期设置为7天，平衡了用户体验和安全性
- 使用Base64编码而非复杂加密算法生成会话令牌，减少计算开销
- 中间件中实现了多层验证机制，避免不必要的数据库查询
- 客户端Hook使用30秒间隔的定期检查，避免过于频繁的验证请求

## 结论
AI求职教练项目的用户认证系统设计合理，通过邀请码机制实现了安全的用户访问控制。系统充分利用了Supabase的身份验证功能，结合自定义的中间件和客户端Hook，构建了一个完整、安全的认证解决方案。建议未来可以考虑增加更多的安全措施，如双因素认证和更复杂的会话管理策略，以进一步提升系统的安全性。
