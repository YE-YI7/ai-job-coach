## 3. 从实际候选进入导师

将 B 搜到的第一条岗位与其简历存入独立岗位，开启会话并实际询问迁移能力、差距、具体练习。导师一轮用时 12832ms，首字 4242ms，模型调用 1 次。

人工阅读这次输出：有区分电商经历与尚未证明的 Agent 能力，给出明确标成练习示例的商家咨询 Agent，并要求用户写工具/边界/兜底三行；没有把假设示例写成用户已完成项目。还指出在读身份与实习时间需要核实。这一例体现导师可开展针对性教学，但筛选端本应先揭示身份条件。输出把 Agent 产品经验称为“硬缺口”，容易混淆能力差距与不可学习补齐的资格门槛，尚需改善。

## 4. 本轮结论和未覆盖

不是“全绿”。导师/记忆/连续面试部分真实运行通过；找岗个性化明确失败。新增对照脚本对任何失败返回非零退出码，保留失败项，不把 HTTP 200 当推荐通过。未修改推荐算法、未部署补丁；只测试和记录。

下一步必须修复：基于用户事实的检索计划与解释；硬资格（含在读状态）明示；硬筛后精选 3–5 条；软差距接入可执行辅导任务。不能只把 9 改为 5，也不能用未经评测的词典计分冒充匹配。

本轮未测：浏览器真实上传分类、真人简历样本、长期异步耐久任务、所有模型切换/失败路径、完整 RAG 切题率和异模型 judge 校准。内置测试会话认证不是手机号/邮箱登录流程验收。
