## 2. 必须修复的缺陷

### F1 · P1 · 已保存成果刷新后回到旧稿，重复保存产生第二份笔记

位置：`components/cockpit/OutcomeCard.tsx:30-49`；`app/api/coach/agent/sessions/route.ts:34`。

浏览器复现：原始答案→编辑为“分母是标注集中全部相关材料，不是实际返回的条数”→保存，显示已保存／记录数 1→刷新，卡片重新显示原始答案／草稿→再保存，记录数变 2，新 ID 与前一次不同。

原因：编辑稿和笔记 ID 仅存在组件 state；回读依旧使用 turn 的旧 outcome。POST 笔记接口每次 insert，没有以成果来源为幂等身份。刷新不会删除第一条笔记，但卡片不能恢复它，容易再次保存旧答案。

修复要求：持久化结构化成果当前版本及笔记关联；按 owner＋来源成果＋请求 ID 幂等保存；重新打开读取当前稿／版本／真实 ID。保存后继续编辑必须变回未保存状态。补刷新、重试、双标签和 409 的组件／接口测试，不能只检查源码包含“已保存”。

### F2 · P1 · 改主意失败会先撤回旧决定，错误文案却说旧选择还在

位置：`lib/coach-harness/repository.ts:553-569`；`app/api/coach/jobs/decisions/route.ts:34`。

复现：mock 第一条 update 成功，第二条 insert 失败。新决定未保存，但旧决定已标 withdrawn；list 读取时会过滤它。新增失败注入用例确认撤回写入已经发生，函数没有恢复步骤。

修复要求：事务／原子更新，或者不会先破坏旧生效记录的版本式提交；失败后真实回读仍为旧决定，双标签不能产生两个生效决定。不得仅修改错误文案。

### F3 · P1 · 岗位决定只有 URL 身份，不能区分推荐批次

位置：`lib/jobs/job-decision.ts` 的 `decisionEntityKey`、`decisionForUrl`；`lib/coach-harness/repository.ts:530-568`。

同 URL 在两次推荐中的键完全一致。保存撤回所有同 URL 的决定，读取也仅保留最新一条；界面只比较材料指纹，不比较推荐批次。同材料新一轮搜索可能直接显示上批决定，没有“这是上批判断”的提示。

此外，决策 POST 只校验 runId／材料指纹的格式，未核对批次归属、批次结果中是否包含此岗、材料版本是否对应。未发现由此读取其他用户数据的证据，但决定的来源绑定不可信。

修复要求：以 owner＋runId＋岗位身份绑定决定；服务端从本人任务结果核对岗位与材料，不能信任客户端自报批次。既往决定可以显示为历史，但不当成本批已表态。

### F4 · P1 · 换目标只维持一轮，改稿模式也无法续接

位置：`lib/coach-harness/teaching-frame.ts:101-145`。

复现一：首问“讲讲 RAG 的评估口径”→“先不学了，帮我改简历这句话”→下一轮提交“我的版本是……”；goal 又变为“讲讲 RAG 的评估口径”。

复现二：“帮我改写简历这句话”→导师请补动作→“我主要负责需求文档和工单归类，没有做开发”；intent 从 revise 变 learn。

原因：goal 始终取第一条首问，换目标仅判断当前消息；intent 只由本轮关键词判定，普通补充默认 learn。

修复要求：保存当前目标／意图／标准版本，只有明确切换才改变；普通补充继承，不能把改稿送回上课。补连续至少三轮的切换／续接用例。

### F5 · P1 · 长一点的困惑提问被记成已作答

位置：`lib/coach-harness/teaching-frame.ts:88-96,129-138`；`app/api/coach/agent/route.ts:299-310`。

复现：“这段 RAG 原理我看了很久还是没有理解，能不能换一个简单例子讲讲”→“懂了”。第一句被放进 attemptTurnIds，下一句进入 closing。若模型此时返回成果标签，这个问题就可被当成用户答案保存。

原因：历史尝试只看字符串，未复用该轮真实 currentIsAttempt／练习状态；≥20 字的许多自然提问都会通过。当前轮与历史轮的作答判定不一致。

修复要求：尝试证据使用已落库、对应练习／标准版本的真实用户作答标记；解释困惑、要求讲解、附和都不是能力证据。既有污染数据不得继续用作成果判定。

### F6 · P1 · 未知资格仍占首屏优先候选位

位置：`lib/jobs/result-presentation.ts` 的 `splitFirstScreen`；`components/cockpit/JobDiscovery.tsx:252-257`。

仅一条 unknown 的候选仍进入 lead。“把 unknown 排后面”不等于 PRD 的“两组分开，未知不占优先位”；只有未知结果时也不应强行凑优先候选。

修复要求：先分 eligible／unknown，再取最多三条优先候选；未知放“先核实条件”组。另补 0 pass、1 pass＋4 unknown、3 pass＋2 unknown 的 UI 与数据分组验收。

### F7 · P1 · 教学收尾仍依赖提示词，未判定当前标准已满足

位置：`lib/coach-harness/teaching-frame.ts:136-159`；`lib/coach-harness/learning-outcome.ts:162-179`。

feedback 路径总要求“指出一个关键缺口并重试”，没有“本题标准已经覆盖”的状态；模型不提供 openIssue 时，服务端反而默认补上“尚未观察独立迁移”。这可能把原本只要求学懂当前机制的用户强行送去新迁移题。

scenarioAudited 只是关键词命中，却把提示词写成“已专项打磨”；当前质量报告的真实内容评测未执行，不能把场景匹配等同于评测通过。

修复要求：本题标准满足可以没有 openIssue；独立迁移是可选的新目标，不是每题必补缺口。专项覆盖状态应来自已核验的场景版本／评测记录，不能由关键词自封。

## 3. UI 与失败状态

- P2：`OutcomeCard.module.css` 新增目标／状态／反馈多为 11–14px，主要按钮 min-height 36px，与本轮 PRD 的 16px 正文／44px 点击区不符。手动 detect 找到新增 `border-left:2px`；未把历史色彩 advisory 一律当回归。建议集中 `$impeccable adapt`／`typeset`／`polish`，本轮不改实现。
- P2：本地 `/cockpit/preview?preparation=1` 实际出现“请先登录”同时显示“供给有限”的零结果说明。`JobDiscovery.tsx:243` 仅凭 `!jobs.length` 画空结果；应分未开始／读取错误／真正完成且零结果。用户未登录、额度失败、来源失败不是“没有合适岗位”。
- 主操作、引用展开、可编辑／复制／失败保留本地草稿等方向正确。问题是持久化与状态转换，而不是把界面全部推倒重来。
- 浏览器成果卡测试容器为窄宽受控页面，不等同 390px 手机整页；没有完成实际手机切栏／滚动位置、长简历 PDF 验收，不能给整站视觉或可访问性满分。

## 5. Evals 与上线门

`docs/architecture/evals/quality-baseline-latest.json` 实际为：50 条登记，25 个结构项通过、25 个内容项 missing；semanticAcceptance=not_evaluated、publishable=false；8 条 E2E 全为 not_run。该报告如实说明边界，不能在交付口径中改称“50 条评测全绿”。

结构集只跑到候选评审池，没有完整执行真实模型排序／个性化理由／三轮导师输出／成果保存。一些断言也不够严格：资格期望只在实际字段存在时比较，去重只比较 id；不能因此证明真实跨来源同岗去重与实际首屏都正确。教学案例注册的轮次亦不等于真实生成轨迹。

发布前：先修 F1–F7 → 将本轮失败用例纳入真正回归 → 真模型跑 40 主案例及 10 反例、按 0/1/2 评分并保留原输出／材料／版本 → 完成 8 条带实际结果的 E2E → 两人校准与 6 人小试点。没有外部用户时只能标受控预览，不能签收正式用户可用。

本轮没有实际真人模型新增调用／真实库保存／30 次延迟采样，没有生产迁移或上线。因此不能声明速率、扣费、手机及用户效果已经验收。原实现保留，修复应限定这些真实缺陷，不删除既有简历、模板、PDF、面试或历史能力。

## 6. 修复复验（2026-10-08，以上为修复前历史）

F1–F7 的代码缺陷已修复，正式发布仍不签收。

- 成果：新增 typed 持久化、来源唯一约束、乐观锁和请求幂等；刷新读编辑后的版本，同一成果修改更新同一条笔记。冲突时保留未保存草稿并允许重新读取后提交，当前对话不被归档。
- 岗位决定：服务端核验 owner、查找批次、材料指纹及批次真实岗位成员；决定按批次＋链接隔离。撤回旧决定和插入新决定在同一数据库事务，失败回滚；重试不重复插入。
- 教学：保存目标、意图与标准版本，普通补充继承改稿模式；困惑提问和附和不作为作答，旧错误标记重新校验。成果完成判断要求依据能逐项回查实际用户回答，反馈与成果状态冲突时不发出假完成成果。迁移题可选，关键词不再自封专项验收。
- 展示：未知资格独立分组，不占前三优先位；结构评测共用真实分组规则。未登录／查找失败不展示供应不足。成果正文 16px、按钮至少 44px，移除新增侧边强调线；既有简历、模板、PDF、面试功能未删除。

- 修复代码可备份到开发分支，但在上述门禁完成前不推 backend 正式发布，不标记 publishable=true。

## 7. 用户要求修复并上线（2026-10-08）

本轮新增真实模型冒烟请求被上游 `Insufficient Balance` 拒绝，停止重复调用；不是新版本成功验收。站点自带DeepSeek服务需要账户所有者充值，不能由Agent擅自购买。已接TokenPay的用户仍走自己的凭据，不能借此声称已复验该用户链路。浏览器控制连接仍超时，25内容校准与8E2E的未验收状态保留。

部署采取干净提交快照（排除auth/admin脏改动）、production staged构建、线上非登录接口烟测后promote。实际发布ID、提交与域名核验结果另记部署报告。
