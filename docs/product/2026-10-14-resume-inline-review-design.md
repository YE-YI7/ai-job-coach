## 用户明确的交互约束

1. 默认只展示修改后的简历。原简历 / 修改建议 / 新成稿不再平铺三 tab；原文件仍须独立保留，不能误删原功能或把 OCR 文本当原件。
2. 模板收进菜单，不常驻三枚按钮。纸面以内容为主，拒绝区块套区块、解释卡片和冗长提示。
3. 待处理修改：绿色荧光笔表示优化 / 新增，黄色表示表达重写，红色荧光笔 + 删除线表示删除。具体语义在实现前整理成可测试的状态，不把整块涂色冒充字符级修改。
4. 提供“显示修改”开关。关闭时显示建议处理后的新内容，红色原文隐藏；只是改变展示，不偷偷替用户采纳或写库。
5. 悬浮 / 聚焦 / 手机点选对应标记时，出现小气泡 ✓ / ×；不常驻成排操作。✓ 采纳后该处标记消失，成为成品；× 撤回该处建议、保留用户原事实。逐条结果需要保存后刷新恢复。
6. 未逐条决定就导出，弹小确认：“要导出的话，按我们最后给你修改的版本导出，你同不同意？”同意则按最终建议版本导出；不同意返回继续选择。已拒绝项不能被“全部采用”重新覆盖；导出不能暗中改旧作答。
7. 区块可拖拽，提示只在首次使用时用一次轻动效；不每块重复写长说明。操作用 grip / 光标 / 短暂移动反馈，保留键盘替代操作；尊重 reduced-motion。

## 排版约束

- 存量简历优先保留用户原有格式、质感和内容，特别是姓名与联系方式；只有原格式严重不合理或内容密度确实需要才调整，不把任意原件套标准模板。
- 新建简历才用标准排版：姓名、电话、邮箱独立清晰且带冒号，右侧保留可选头像位置。没上传照片不制造假照片；预览里的生成头像不进入用户成稿。
- 一页优先，不以静默删真实事实或缩到不可读为代价。bullet 短、具体、可核实，拒绝名词堆砌。
- 图中内容只是设计占位，第一张尾部仍有泛化技能文案，不作为真实生成质量范本；第二张已要求具体动作与对象。示意图也不证明原 PDF / DOCX 可以原位无损编辑，工程实现需单独验证原件与编辑层的边界。
