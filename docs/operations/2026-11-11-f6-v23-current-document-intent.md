## 改了哪层

1. `resume-editing-context.ts` 是本次唯一新增的运行职责：复用现有编辑器投影，把当前稿、原始事实来源、本轮意图、历史要求分开。当前稿含待确认预览与已作取舍；不使用旧生成文件覆盖人工决定。无法投影就在模型和额度预留前明确失败，不静默回退旧原稿。
2. 原任务入口把实际动作交给执行器。重新修改整份时，不再将最后一条历史 instruction 自动赋给 `editingRequest`；历史原文/时间仍可读，由原作者判断哪些方向仍适用。新的明确修改或对话接续要求照常传入。重启也不再把旧聊天冒充最新用户消息。未删除历史作答。
3. F6 首输入与 `read_file(resume.md)` 同为当前稿。原始稿另标为仅核源，历史决定仅传 ID/位置/状态，不重复塞整段旧 before/after。差异保存仍锚定原始稿，原 CAS、撤销、采纳与拒绝语义不变。当前稿计入必要上下文预算，不截断后继续。
4. HR 新增独立标注的当前稿比较文档，明确它不是事实来源；原稿与补充仍用于核源，新稿仍是唯一评审对象。不会拿旧原稿早已完成的改善作为本轮成果。
5. 若交付正文与当前稿相同，只多精确 PAGEBREAK 注释或不可见空白，保存为 `unchanged`，保留原建议 ID/状态，说明“本轮没有新增正文修改”，沿原无新增修改规则释放额度，而不是又造一条待确认修改。标点修复、真实条目/段落结构变化仍保留，不靠相似度阈值拒稿。
6. 未变正文也照常保存显式 `mentor.md` / HR 文件；仅分页差异不使刚发出的具体问题在刷新后变成过期指导。导师职责补清：会改变贡献、责任、取舍或验证结论的缺口，不能只归到内部“面试准备”；仍由原作者判断并发给用户，不强制每轮问、不解析 HR 自然语言生成问题。

没有增加模型、语义解析器、固定工具顺序或自动重试；原 F6/B05、五工具及案例内容不替换，模型选择、12 作者/4 公网/1 HR 上限保持。该修复也不冒称补齐了个人历史 Memory 的自主检索能力。
