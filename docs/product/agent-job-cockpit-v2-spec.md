# 益职求职作战盘 V2 产品规格

> 状态：讨论稿，供产品、设计与工程评审
> 日期：2026-08-14
> 主分支：`backend`
> 产品名称：益职 AI
> 线上域名：<https://ai-job-coach.xin>
> 版本主题：把求职焦虑转化为可验证的证据与下一步

> 2026-08-31 用户反馈：即使做出计划中的功能，仍可能继续使用 ChatGPT 求职。该反馈作为第一阶段的替代风险记录；先完成事实真源、岗位快照与质量闸门，再验证这些持续性能力是否足以改变使用选择。

## 0. 执行摘要

V1 确立了“岗位机会 + 可视作战盘 + Agent 执行”的产品结构。V2 要回答更重要的问题：用户为什么会持续回来，而不是完成一次简历修改后离开？

答案不是增加更多 AI 生成器，而是接住求职过程中反复出现的失控感。

求职者最常见的真实状态不是“我缺一封求职信”，而是：

- 这个岗位到底值不值得花时间？
- 我被拒是因为能力不够、表达不好，还是岗位本来就不真实？
- 我已经做了很多，为什么仍然没有反馈？
- 面试快到了，我最可能在哪个问题上失手？
- 同时有五个机会，我今天应该救哪一个？
- AI 改出来的内容看起来厉害，但还是不是我？

V2 的核心产品命题：

> 焦虑不是一条需要被安慰掉的情绪，而是一组没有被命名、验证和排序的不确定性。益职让 AI 把它们转成证据、问题和行动。

V2 的产品类别不再定义为“AI 求职助手”，而是：

> **面向求职者的 AI 决策与执行系统。**

核心切入点：

1. 以岗位机会为长期状态，而不是一次生成任务；
2. 以证据和不确定性解释结论，而不是只给匹配分；
3. 每次只推荐一个最能改变判断或结果的动作；
4. AI 主动维护跨阶段上下文，用户不必反复讲述自己；
5. 所有 AI 产物都能追溯、修改和否决，不侵蚀用户的真实身份。

V2 还有一个不可退让的修正：

> 作战盘不是装材料的外壳，AI 也不是用户进入某个页面后才出现的按钮。作战盘是 AI 教练持续观察、判断、发起动作并留下结果的工作现场。

简历工作室、模拟面试圆桌、面试复盘和网申协作全部返场，但遵循渐进呈现：平时不堆在概览里；当阶段、风险或用户意图触发时，AI 才提出一张有理由的行动卡，用户点开后进入完整工作空间。

## 1. 竞品研究结论

### 1.1 竞品不是同一种产品

当前产品可分成五组：

| 类型 | 代表产品 | 用户购买的结果 | 强项 | 主要缺口 |
| --- | --- | --- | --- | --- |
| 求职记录与简历工作台 | Teal、Huntr、Careerflow | 管理申请、提高简历匹配度 | Tracker、简历版本、ATS、关键词 | 更像工具集合，较少持续解释“为什么现在做这一步” |
| 申请效率与岗位发现 | Simplify、Jobright、LoopCV、Sonara | 找更多岗位、少填表、投得更快 | 聚合、匹配、浏览器 Autofill、Auto-apply | 优化吞吐量，容易把“更多申请”误当成“更接近 Offer” |
| 面试临场辅助 | Final Round AI、Verve、Interviews Chat | 降低面试当下的认知压力 | 实时转写、建议回答、模拟、复盘 | 只占据面试时刻，且隐形答题存在真实性和信任风险 |
| 通用大模型 | ChatGPT、Claude、Codex | 低成本完成任意单次任务 | 推理与生成能力强、灵活 | 没有稳定求职状态、专用数据结构和持续作战界面 |
| Agent 原生垂直产品 | ChatCut | 让 Agent 真实操作一个可见项目 | 项目、可编辑产物、Agent 与人工接管、额度确认 | 不是求职产品，但其交付结构值得直接学习 |

### 1.2 各对标最值得学习的颗粒度

#### Teal：免费记录，付费提升 AI 深度

Teal 将 Job Tracker、基础简历与部分匹配能力作为免费入口，将无限简历版本、深入分析、关键词匹配和更多 AI 能力放进 Teal+。官方页面同时提供周、月和 90 天周期，符合求职具有强周期性、用户不愿承诺全年订阅的特点。

应该学习：

- 免费工具先承接用户正在发生的求职项目；
- 付费点发生在“我要提高这个岗位的成功质量”时；
- 订阅周期匹配短期高强度求职，而不是强迫长期会员。

不直接照搬：

- 用 Match Score 作为主要价值表达；
- 把大量独立生成器作为产品导航。

来源：[Teal+ Pricing](https://www.tealhq.com/pricing)

#### Huntr：一个 Job Card 驱动后续所有产物

Huntr 把岗位卡片作为职位信息、JD、简历定制、面试准备、截止时间和跟进的中心对象。其 Resume Tailor 允许用户逐项接受、编辑或拒绝建议，并解释修改理由。免费试用后，AI 深度能力形成明确的月度付费信号。

应该学习：

- 一个岗位对象驱动简历、面试与跟进；
- 每条 AI 修改都给理由并允许局部接受；
- 浏览器 Clipper 降低收岗位成本。

不直接照搬：

- 关键词覆盖主导的“优化游戏”；
- 把生成成就描述等同于找到真实证据。

来源：[Huntr 产品说明](https://help.huntr.co/en/articles/10477521-what-is-huntr)、[Huntr Resume Tailor](https://api.huntr.co/product/resume-tailor)

#### Simplify：占据投递发生的页面

Simplify Copilot 通过浏览器扩展在 Workday、Greenhouse、Lever 等申请页面直接填表，并在提交后自动进入 Job Tracker。其 Talent Agent 进一步承诺岗位匹配、简历定制、关系发现、下一步建议和代申请。

应该学习：

- 产品入口出现在用户正在投递的页面，而不是要求用户回到另一个聊天窗口；
- 已回答的重复问题可以结构化复用；
- 用户提交后自动更新状态，减少手动维护作战盘。

不直接照搬：

- V2 不做自动海投；
- 不把申请数量作为成功代理指标；
- 未经确认不替用户发送任何材料。

来源：[Simplify Copilot](https://simplify.jobs/copilot)、[Simplify AI Talent Agent](https://simplify.jobs/ai-talent-agent)

#### Jobright：发现、匹配、简历与关系链放在一起

Jobright 将岗位聚合、AI 匹配、简历定制、内部关系推荐、Autofill 和 24/7 Copilot 放在一条链路里，价值表达是“不再独自找工作”。

应该学习：

- 不只分析用户找到的岗位，也可以主动发现值得投入的机会；
- 匹配解释应同时考虑技能、经验、地点、薪资和偏好；
- “有人持续替我看着机会”比“我有一个 AI 生成器”更接近用户感受。

不直接照搬：

- 岗位聚合和内部推荐需要巨大的数据与渠道优势，不适合作为当前第一战场；
- 不使用无法独立验证的成功率和节省时间数字。

来源：[Jobright](https://jobright.ai/)

#### Final Round AI：最高焦虑时刻有最高付费意愿

Final Round AI 直接占据真实面试这一高压时刻，提供实时转写、结构化回答提示、模拟与面后分析。其商业信号说明，用户愿意为临近面试的确定性和即时支持支付明显高于普通简历工具的价格。

应该学习：

- 按“高焦虑事件”包装能力，而不是按技术模块包装；
- 面试前准备、面试中支撑、面试后复盘属于同一事件闭环；
- 在信息过载时只给结构和关键提示。

不直接照搬：

- 不做隐形实时代答；
- 不鼓励用户在真实面试中陈述未经确认的 AI 内容；
- 不把“看不见”当作产品价值。

来源：[Final Round AI 产品说明](https://www.finalroundai.com/blog/what-is-final-round-ai)、[Final Round AI FAQ](https://www.finalroundai.com/frequently-asked-questions)

#### ChatCut：AI 必须操作真实项目，而不是只回复文字

ChatCut 的关键不是聊天面板，而是 Agent、素材、时间线、预览和导出共同组成的可编辑项目。AI 任务消耗额度，手工浏览、预览、编辑和导出不消耗额度；涉及生成成本时在上下文中确认。

应该学习：

- 用户始终看见 Agent 正在修改什么；
- AI 结果直接落在结构化项目里，人工可以随时接管；
- 消耗额度的动作在发生前给出清楚确认；
- 复杂工作流可以保存为可复用能力，但 Skill 本身不是最终产品。

益职对应关系：

| ChatCut | 益职 V2 |
| --- | --- |
| 视频项目 | 岗位机会 |
| 素材 | JD、经历证据、简历、面试记录 |
| 时间线 | 投递、沟通、面试与结果事件 |
| 预览 | 当前岗位判断与风险 |
| Agent 编辑 | AI 更新证据、产物和行动 |
| 人工微调 | 用户确认事实、修改简历、调整决策 |
| 生成确认 | 模型额度与对外动作确认 |
| 导出 | 简历、面试作战书、沟通文本、复盘 |

### 1.3 五重过滤后的主对标

| 对标 | 商业信号 | 模型是否看懂 | 当前是否能模仿 | 决策 |
| --- | --- | --- | --- | --- |
| Huntr | 免费入口 + 明确 AI 月费 | 看懂：Tracker 获客，AI Tailor 转化 | 高 | 核心产品结构对标 |
| Teal | 免费 Tracker + 多周期 Teal+ | 看懂：先沉淀求职数据，再卖深度能力 | 高 | 商业分层对标 |
| Simplify | 免费 Autofill 扩展 + Premium Agent | 看懂：扩展获客，平台与高级 AI 变现 | 中 | 学入口，不在 V2 拼 ATS 兼容规模 |
| Final Round AI | 高压事件带来高客单 | 看懂：面试临近触发强付费 | 中 | 学事件包装，不学隐形代答 |
| ChatCut | Agent 额度 + Pro 能力 | 看懂：免费编辑器沉淀项目，AI 消耗变现 | 高 | Agent 产品交付对标 |
| Jobright | 聚合、匹配、关系与 Copilot | 主干看懂，但依赖岗位和关系数据 | 低 | 学主动性，不正面拼供给 |

结论：

> 益职最值得模仿的组合不是某一个竞品，而是 Huntr 的岗位对象、Teal 的商业分层、Final Round AI 的焦虑时刻定价和 ChatCut 的 Agent 项目交付。

## 2. 用户焦虑模型

### 2.1 产品只处理“求职不确定性”，不提供心理治疗

益职可以识别用户表达的压力、犹豫和失控感，但不诊断焦虑症、抑郁或其他健康问题，也不承诺改善心理健康。

产品语言应做到：

- 承认用户面临的不确定性；
- 说明当前已知、未知和可控制部分；
- 给出有限、具体、可完成的下一步；
- 允许暂停、放弃岗位或关闭提醒；
- 当用户表达自伤或严重危机时，停止普通求职流程并建议寻求即时专业帮助。

### 2.2 八个高焦虑时刻

| 时刻 | 用户内心问题 | 真实缺口 | 竞品常见回答 | 益职应该回答 |
| --- | --- | --- | --- | --- |
| 看到 JD | “我够格吗？” | 要求不清、证据没被提取 | 给一个 Match Score | 哪些要求有证据、哪些是假性缺口、是否值得投入 |
| 准备投递 | “这样改会不会不像我？” | 事实边界与表达边界混淆 | 自动重写整份简历 | 每处修改来自什么证据、哪些内容待确认 |
| 投递完成 | “是不是还应该多投几十个？” | 缺少质量与注意力预算 | 鼓励更高申请量 | 当前组合是否过度集中、今天最值得新增哪个机会 |
| 等待回复 | “没消息是不是我不行？” | 无法区分流程延迟、岗位风险和材料问题 | 继续提醒 Follow-up | 给出等待基线、可控动作和停止投入条件 |
| 面试临近 | “我会在哪道题卡住？” | 工作记忆压力、故事调用困难 | 大量题库或实时代答 | 只训练最可能改变结果的 2–3 个薄弱证据 |
| 面试结束 | “那句话是不是说错了？” | 回忆偏差、反刍、没有结构化记录 | 生成泛化复盘 | 区分事实、推断与无法知道；保存决定性片段和训练任务 |
| 被拒绝 | “是不是我根本不行？” | 单次结果被泛化为自我判断 | 发送鼓励文案 | 只更新本次机会的证据和策略，不把一次拒绝推断为长期能力 |
| 多机会并行 | “每个都急，我先做什么？” | 截止时间、价值、风险和投入混在一起 | 看板记录状态 | 排出今天最多三个动作，并解释放弃了什么 |

### 2.3 焦虑的四种可计算来源

每条用户担忧映射到以下一种或多种来源：

1. **信息未知**：不知道岗位真实要求、流程或反馈；
2. **证据不足**：知道要求，但没有足够真实经历支撑；
3. **行动冲突**：知道能做什么，但时间和机会之间冲突；
4. **结果不可控**：用户已完成合理动作，剩余结果取决于招聘方。

系统不得把第四类伪装成仍需用户努力。明确告诉用户“现在没有更高价值动作”也是有效交付。

### 2.4 研究依据

- 面试焦虑与面试评分之间存在负相关，说明结构化准备不是装饰，而会影响用户表现。[Wiley 研究](https://onlinelibrary.wiley.com/doi/full/10.1111/ijsa.12263)
- Gartner 2025 年候选人调查中，只有 26% 相信 AI 会公平评价自己；32% 担心 AI 让申请失败，且只有一半相信申请的岗位真实存在。这说明“AI 可信”和“岗位真实性”本身就是焦虑来源。[Gartner 调查](https://www.gartner.com/en/newsroom/press-releases/2025-07-31-gartner-survey-shows-just-26-percent-of-job-applicants-trust-ai-will-fairly-evaluate-them)
- 对技术中介面试的研究把焦虑拆成沟通、外表、社交、表现和行为等维度，支持益职在面试前给出针对性训练，而不是泛题库。[PMC 研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC7835329/)

## 3. V2 产品定位与切入点

### 3.1 一句话定位

> 益职把每个岗位里说不清的焦虑，变成有证据的判断和今天能完成的一步。

### 3.2 用户不是购买“AI”，而是购买三种确定性

1. **决策确定性**：这个岗位是否值得继续投入；
2. **表达确定性**：我说的每句话都来自真实经历；
3. **行动确定性**：今天完成什么，而不是无限准备。

### 3.3 第一切入点

V2 不从“完整求职平台”切入，而从以下最小闭环切入：

```text
一个真实 JD
→ AI 拆要求并连接真实经历
→ 明确最大未知与用户最担心的点
→ 只问一个高信息量问题
→ 给出投 / 补 / 弃判断
→ 生成一个可执行下一步
→ 把结果留在持续作战盘
```

这个闭环比简历生成更早，比自动投递更可信，也能自然进入简历、面试与复盘。

### 3.4 0→1 切入策略：用决策激活，用战役转化

获客入口和首次付费时刻不应强行设计成同一个动作：

1. **免费 / 低成本激活：一个 JD 值不值得投。** 用户只需提供 JD 和现有简历，10 分钟内得到证据化判断、最大未知和一个下一步。这个入口高频、容易理解，也能建立后续岗位状态。
2. **首次付费转化：重要面试前 24–72 小时。** 此时截止时间明确、焦虑强、历史材料已经沉淀，益职可以交付三个决定性问题、针对性模拟、薄弱证据补强和一页作战书；价值比“再生成一份简历”更可感知。
3. **持续留存：等待心跳和多岗位注意力。** 付费后通过阶段跟进、面后复盘和机会优先级持续维护求职项目，而不是用无意义提醒制造活跃。

因此，V2 的第一增长漏斗是：

```text
JD 决策激活
→ 保存为岗位机会
→ 完成真实证据补充
→ 面试关键战役付费
→ 面后复盘与等待心跳留存
```

### 3.5 明确不竞争的方向

V2 不正面竞争：

- 全网岗位聚合数量；
- 所有 ATS 的自动填表覆盖；
- 自动海投；
- 隐形实时面试代答；
- 低价批量生成求职信；
- 单次简历分数。

## 4. AI 能力定义

### 4.0 AI 教练运行时

益职只有一个贯穿全程的 AI 教练，不为简历、面试和复盘分别创造彼此失忆的聊天机器人。

它持续维护两层上下文：

1. **长期求职记忆**：用户确认过的经历、项目、结果指标、表达偏好、历次模拟和真实面试中重复出现的模式；
2. **当前岗位记忆**：JD、岗位判断、证据关系、定制简历版本、投递记录、面试安排、模拟记录、真实面试记录和下一动作。

“AI 记得全部”不等于每次把全部原文塞进模型。系统应先读取结构化摘要和索引，再按当前任务检索相关原文片段，既节省 Token，也避免不必要地暴露材料。任何被调用的记忆都必须显示来源，用户可以更正、遗忘或禁止跨岗位复用。

### A1. 求职状态重建

AI 从用户明确提供的 JD、简历、面试记录和历史动作中重建当前岗位状态。

输出必须区分：

- 原始事实；
- 用户已确认事实；
- AI 推断；
- 尚未知信息；
- 已过期信息。

### A2. 证据图谱

AI 不只做关键词匹配，而是建立：

```text
岗位要求
→ 用户证据
→ 证据来源
→ 强弱与可信状态
→ 已用于哪些简历表述
→ 在面试中是否被验证
→ 最终结果
```

同一条证据可以跨岗位复用，但每个岗位的适用性和表达方式独立保存。

### A3. 不确定性拆解

任何“适合度”“风险”或“建议”都必须回答：

- 已知什么；
- 不知道什么；
- 哪个未知会改变结论；
- 如何用最低成本验证；
- 如果无法验证，默认采取什么保守策略。

禁止把模型概率直接表述为 Offer 概率。

### A4. 下一最佳行动排序

系统对候选动作计算相对优先级：

```text
行动价值 = 机会价值 × 改变判断的可能性 × 时效性
         ÷ 预计耗时
         - 事实风险
         - 用户负荷
```

该公式用于排序，不向用户展示虚假精确数字。界面只解释两到三个决定排序的原因。

### A5. 主动提问

AI 一次只问一个问题，并优先选择信息价值最高的问题。

一个问题只有在满足以下条件时才可以主动出现：

1. 答案可能改变投递、简历或面试策略；
2. 现有材料中找不到可靠答案；
3. 用户能够在合理时间内回答；
4. 当前没有更紧急的截止事件；
5. 同类问题近期没有被延后或拒绝。

### A6. 可追溯生成

简历、沟通文本和面试故事中的每一条新增内容必须链接到：

- 原始经历；
- 用户补充回答；
- 或清楚标记为待确认占位。

AI 可以重组和改写，不能补造事实。用户能够逐项接受、修改和拒绝。

### A7. 针对性模拟

模拟面试不是随机题库。AI 根据以下信息选择问题：

- JD 高权重要求；
- 简历中被强化的表述；
- 证据薄弱但可能被追问的区域；
- 公司与岗位阶段；
- 用户过往模拟和真实面试中的重复弱项。

每轮只训练少量目标，并在结束后更新证据和行动。

### A8. 事件心跳

AI 持续监控：

- 截止时间；
- 面试临近；
- 等待回复时长；
- 未确认关键事实；
- 岗位长时间停滞；
- 多岗位注意力冲突。

心跳不是鼓励文案，而是一条带理由、截止时间和关闭方式的行动建议。

### A9. 结果学习

AI 从投递、面试和结果中更新策略，但必须避免：

- 用一次拒绝否定某项能力；
- 把相关性当因果；
- 在没有招聘方反馈时猜测拒绝原因；
- 为了形成故事而伪造“规律”。

只有跨多个机会重复出现、且有直接证据的模式，才能进入长期训练主题。

### A10. Agent 工具执行

Agent 版允许 AI 在用户沙箱中：

- 读取用户明确提供的文件；
- 创建或更新岗位机会；
- 保存结构化产物；
- 启动本地可视作战盘；
- 返回本地页面而非长篇聊天输出。

任何对外发送、自动投递和云端同步均需要额外明确授权。

### A11. 网申协作

在宿主提供浏览器控制或用户安装浏览器扩展时，AI 可以：

- 打开用户指定的招聘页面；
- 识别可填写字段；
- 复用已确认的个人资料和当前岗位申请包；
- 生成开放题草稿，并显示证据来源；
- 填入页面但停在提交前；
- 把每个动作和失败原因实时写回作战盘。

以下动作始终要求用户确认：最终提交、隐私与人口统计字段、薪资期望、签证 / 背调声明、上传文件版本以及任何可能产生法律含义的回答。验证码和反自动化限制不绕过，失败时降级为“可复制的申请答案包”。

### A12. 主动教练

主动不是一天发一条提醒，而是 AI 发现状态变化后，判断是否值得打扰用户：

```text
事件或状态变化
→ 规则层筛出可能重要的信号
→ AI 读取相关记忆并判断影响
→ 生成一条“为什么现在”的介入
→ 用户开始 / 延后 / 忽略 / 关闭
→ 结果写回记忆并影响下次主动性
```

主动教练可以提出新动作、启动工作空间、发现跨岗位规律，也必须知道什么时候不说话。

## 5. 核心体验：焦虑—证据—行动闭环

### 5.1 机会首页必须同时回答四个问题

1. 我现在最担心什么？
2. 当前证据支持什么判断？
3. 最大的不确定性是什么？
4. 今天做什么最可能改变结果？

### 5.2 焦虑卡不是情绪打卡

用户可以直接输入一句担忧，例如：

> “我没有大厂背景，这个岗位是不是根本不会看我？”

AI 将其转换为：

```text
担忧：公司背景可能是隐性门槛
已知：JD 未要求特定公司背景
证据：用户有同规模业务问题的直接项目结果
未知：招聘方是否把同类平台经验作为筛选条件
可控动作：在简历首屏突出复杂度与业务规模，而不是公司名称
停止条件：若岗位明确补充特定平台经验为硬门槛，重新评估
```

系统不得回答“相信自己”“你很优秀”等无法验证的安慰。

### 5.3 控制地图

每个机会展示四区：

| 区域 | 含义 | 系统动作 |
| --- | --- | --- |
| 已确认 | 有来源、用户确认 | 可以进入产物 |
| 待验证 | 可能改变判断 | 主动提问或建议验证 |
| 可行动 | 用户今天能完成 | 进入今日行动 |
| 不可控 | 招聘方决定或无法获得 | 不继续制造任务 |

### 5.4 完成态

一个机会阶段不是“AI 已生成”，而是：

- 用户做出了清楚决策；
- 关键事实已确认或明确接受未知；
- 下一动作已经完成、延后或放弃；
- 产物可追溯；
- 作战盘状态已更新。

### 5.5 AI 的渐进呈现

AI 不以一个永久展开的聊天栏占据所有页面，而以四种层级出现：

| 层级 | 何时出现 | UI 形态 | 用户动作 |
| --- | --- | --- | --- |
| 状态 | AI 正在读取或执行 | 顶部轻量状态、动态时间线 | 查看读取范围或取消 |
| 提议 | 发现值得处理的问题 | 右栏教练卡，只显示理由和收益 | 开始、延后、忽略 |
| 工作 | 用户接受任务 | 抽屉、分屏或全页工作空间 | 与 AI 共同完成 |
| 结果 | 一次 AI 任务完成 | 差异、证据、结论和下一步 | 接受、修改、拒绝 |

简历和面试标签页在没有需要时保持安静。出现需要后，标签显示一个有语义的状态，例如“1 个关键表述待补强”或“明天面试 · 建议模拟 15 分钟”，而不是没有解释的红点。

## 6. 两个版本的 V2 边界

### 6.1 付费网页版

益职提供：

- 托管账号与云端作战盘；
- 模型调用；
- 多岗位同步；
- 异步深度分析；
- 事件心跳；
- 跨设备访问；
- 后续可选的日历和通知连接。

付费原则：

- 浏览、手工编辑和导出不消耗模型额度；
- 需要模型推理或生成的动作消耗额度；
- 深度分析开始前展示预计消耗区间；
- 失败的生成不扣除额度；
- 不在 V2 spec 中虚构具体价格，必须通过真实成本和用户测试确定。

### 6.2 免费 Agent 版

益职提供：

- 免费 Plugin / Skills；
- 本地 MCP；
- 本地可视作战盘；
- 求职方法、Schema 和工作流；
- 官网 Agent 执行手册。

用户自己的 Agent 提供：

- 模型；
- 沙箱与文件权限；
- Agent 宿主套餐或额度。

默认数据位置为 `~/.yi-zhi/`，不自动同步到益职云端。

### 6.3 双版本关系

两个版本共享：

- 焦虑—证据—行动方法；
- 核心数据结构；
- 可信边界；
- 可导出产物格式。

V2 默认不承诺云端与本地自动同步。未来同步必须由用户主动启用，并提供预览、冲突处理和撤销。

### 6.4 同一功能，两种 AI 执行器

所有产品动作使用统一的 `CoachAction` 契约，界面不因模型来自哪里而改变：

| 运行方式 | 谁负责推理 | 如何执行 | 结果写到哪里 |
| --- | --- | --- | --- |
| 付费网页版 | 益职现有模型 API | Next.js API / 后台任务 | Supabase 岗位项目 |
| 本地 Agent 版 | 用户当前 Agent | Skills 负责决策，MCP 负责读写本地项目 | `~/.yi-zhi/` 本地项目 |

网页端现有简历定制、双 HR 讨论、模拟面试、多角色复盘 API 可以作为第一批执行器迁入作战盘，不需要重写一套模型能力。迁移重点是统一输入上下文、输出 Schema、版本记录和主动触发。

### 6.5 Agent 互联的能力边界

ChatCut 式“Agent 修改、界面实时可见”可以做到：Agent 通过 MCP 更新项目，本地作战盘通过事件流读取最新状态并展示过程。

反方向“用户在作战盘点按钮，立刻唤醒任意个人 Agent”不能假设所有宿主都原生支持。V2 定义三级互联：

1. **Level 0：会话接续。** 作战盘把请求写入本地命令队列；用户回到 Agent 说“继续”，Agent 领取并执行。所有宿主可用。
2. **Level 1：在线互联。** Agent 会话仍在运行时持续领取命令，用户在作战盘点击“开始模拟”后，Agent 直接执行并流式回写。支持持续工具循环的宿主可用。
3. **Level 2：主动唤醒。** 用户明确安装并授权本地守护进程或宿主定时任务后，截止、面试和停滞事件可以唤醒 Agent。按 Codex、Claude Code、WorkBuddy 分别适配，不伪装成通用 MCP 能力。

界面必须显示当前互联等级和真实状态，例如“Agent 在线”“等待你回到 Agent”“本地心跳已开启”，不能让用户误以为已经在后台执行。

### 6.6 本地 Agent 命令闭环

```text
用户在作战盘发起动作
→ 本地页面写入 CoachCommand
→ 在线 Agent 通过 MCP 领取命令
→ Agent 读取 ContextBundle
→ Agent 持续回写 progress events
→ 作战盘通过 SSE 刷新过程
→ Agent 保存结构化结果和 ArtifactVersion
→ AI 教练重新计算下一步
```

现有五个本地 MCP 工具保留，新增最小工具面：

- `yi_zhi_get_context_bundle`：只返回当前动作所需的岗位、证据和历史摘要；
- `yi_zhi_list_signals`：读取未处理的主动信号；
- `yi_zhi_claim_command`：领取一个待执行动作，避免重复处理；
- `yi_zhi_report_progress`：把正在读取、执行、等待确认或失败写回页面；
- `yi_zhi_complete_command`：提交结构化结果并更新状态；
- `yi_zhi_save_artifact_version`：保存带来源和父版本的产物。

本地页面只创建业务命令，不直接向 Agent 注入任意提示词；Agent 对来自 JD、网页和附件的指令内容继续按不可信输入处理。

## 7. V2 信息架构

### 7.1 顶层结构

```text
今日
├── 最重要的一步
├── 临近事件
└── 等待与停滞

岗位机会
├── 判断
├── 证据
├── 简历
├── 面试
├── 沟通
├── 复盘
└── 动态

我的证据
├── 经历事实
├── 项目档案
├── 结果指标
├── STAR 故事
├── 简历版本历史
├── 模拟与真实面试历史
├── 跨岗位重复训练主题
└── 待确认事实
```

AI 教练不单独占一个顶层页面。它通过“今日”、每个岗位的提议卡、按需工作空间和动态时间线贯穿全产品；“我的证据”是用户查看和纠正 AI 长期记忆的控制面。

### 7.2 机会概览布局

```text
┌ 机会状态与关键事件 ───────────────────────────────┐
│ 公司 / 岗位 / 当前阶段 / 截止时间 / 停止投入条件 │
├ 当前判断 ───────────────┬ 当前最大不确定性 ───────┤
│ 投 / 补 / 弃             │ 会改变判断的一个未知     │
│ 证据摘要                 │ 验证方式                 │
├ 用户正在担心什么 ───────┴ 今日最重要的一步 ───────┤
│ 担忧 → 已知 / 未知 / 可控 / 不可控               │
├ 产物与时间线 ─────────────────────────────────────┤
│ 简历版本 / 面试作战书 / 沟通 / 复盘 / 事件        │
└───────────────────────────────────────────────────┘
```

## 8. V2 功能规格

### F1. 一句话收岗位

输入：JD 链接、文本、截图或文件。

输出：

- 原始 JD 快照；
- 公司、岗位、地点、薪资和截止信息；
- 信息时效与来源；
- 硬门槛、核心任务和偏好项；
- 疑似过期、重复或信息不足提示；
- 首个决策问题。

### F2. 值不值得投 2.0

输出不再以匹配分开头，而以决策开始：

- `优先投递`
- `补充后投递`
- `低成本试投`
- `暂不投入`

必须展示：

- 支持结论的强证据；
- 反对结论的硬缺口；
- 最大未知；
- 预计补充成本；
- 机会成本；
- 何种新信息会改变结论；
- 一项下一动作。

### F3. 用户担忧捕获

系统允许用户在任意机会中输入一句“我现在最担心的是……”。

AI 必须：

1. 复述为具体可检验的问题；
2. 标注属于信息、证据、行动或不可控问题；
3. 连接已有证据；
4. 给出一个动作或明确当前无需动作；
5. 允许用户标记“不是我担心的重点”。

### F4. 证据库 2.0

新增：

- 证据使用历史；
- 哪些岗位要求使用过；
- 简历、模拟和真实面试中的表现；
- 证据强度变化；
- 冲突事实检测；
- 用户撤回或更正。

### F5. 一岗一版申请包

一个申请包包括：

- 定制简历；
- 可选求职信；
- 申请问题回答；
- 招聘沟通文本；
- 修改差异；
- 事实来源；
- 用户确认状态。

用户逐项确认后才进入“可发送”状态。

#### F5.1 AI 简历工作室按需展开

触发条件包括：岗位判断为值得投、当前没有岗位版本、JD 发生变化、证据新增后可显著改善表述，或用户主动点击“让 AI 帮我改”。

触发前只显示一张教练提议：

- 为什么现在需要改；
- 预计改动范围和模型消耗；
- 会读取哪份简历、哪些证据和哪个 JD；
- `开始优化 / 先补证据 / 暂时不改`。

点开后进入分屏工作室：左侧原简历，中间逐条差异与来源，右侧为 AI 教练。旧版“双 HR 看简历”返场为可选的“听听招聘视角”模式，只讨论当前修改和岗位要求，不常驻概览，也不把角色对话当作最终结论。

### F6. 面试关键战役

面试前页面只显示：

- 三个最可能决定结果的问题；
- 每题对应证据；
- 一个最危险的追问；
- 两个需要记住的数字或事实；
- 面试官可能质疑的点；
- 15 分钟、30 分钟和完整训练入口。

不默认显示几十道题库。

#### F6.1 AI 模拟面试圆桌返场

圆桌不是被删除的旧页面，也不是一直铺在面试标签下，而是“面试关键战役”的完整工作空间。

触发条件：用户录入面试时间、岗位进入 `interviewing`、AI 发现决定性证据尚未训练，或用户主动要求模拟。

进入前的提议卡显示：

- 为什么建议现在模拟；
- AI 已读取的 JD、岗位简历和历史弱项；
- 建议时长与本轮训练目标；
- `15 分钟重点练 / 30 分钟完整模拟 / 自定义`。

模拟过程中：

1. 一位主面试官按真实节奏一次只问一题，并根据回答追问；
2. 回答时不同时展示六个角色的长篇意见，避免增加认知负担；
3. 每个小节结束后，可展开圆桌：业务负责人看岗位判断、专业面试官查能力深度、HR 看表达与动机、导师查逻辑、教练识别焦虑与卡顿；
4. 角色可以补充或反驳，但最终由总教练合并成一个结论和一个训练动作；
5. 模拟结束后，问题、回答、圆桌讨论、改写、训练任务和证据变化全部写回当前岗位。

旧的六角色资产、多角色分析、逐题流式讨论、答案改写和训练任务 API 优先复用；视觉语言收敛到现有作战盘，不恢复旧页面中过度热闹的独立世界。

### F7. 面后去反刍复盘

复盘首先区分：

- 发生的事实；
- 用户当时的感受；
- AI 可以合理推断的风险；
- 无法知道的招聘方判断。

最终只输出：

- 做得好的决定性片段；
- 一个需要修复的片段；
- 是否需要 Follow-up；
- 下一轮训练任务；
- 本机会下一状态。

### F8. 等待与沉默处理

每个阶段配置等待基线，而不是每天提醒。

系统根据：

- 用户上次动作；
- 招聘方承诺时间；
- 岗位阶段；
- 已发送 Follow-up 次数；
- 其他机会优先级；

给出 `继续等待 / 发送一次跟进 / 降低优先级 / 关闭机会` 建议。

### F9. 今日注意力预算

每日最多推荐三个动作，默认只突出一个。

每项动作必须包含：

- 为什么是现在；
- 会改变什么；
- 预计耗时；
- 截止时间；
- 完成、延后、放弃和静音入口。

### F10. 求职组合风险

系统不是只管理单岗位，也要发现组合问题：

- 所有机会集中在同一公司类型；
- 目标岗位跨度过大导致证据无法复用；
- 只有高难度机会，没有保底机会；
- 大量低价值申请占用时间；
- 面试密集冲突；
- 长期没有新机会进入。

只在样本足够时提示，不能用两三个岗位过度概括。

### F11. Agent 协助网申

当申请包所有关键事实已确认，机会页出现“让 Agent 帮我填网申”。入口不在全局导航常驻，只在 `preparing_application` 阶段出现。

执行工作台必须让用户实时看到：

| 状态 | UI |
| --- | --- |
| Agent 正在打开页面 | 当前网址、页面标题、停止按钮 |
| 字段已识别 | 字段总数、自动可填、需确认、无法处理 |
| 正在填入 | 当前字段、采用的答案与来源 |
| 需要用户决定 | 原位确认卡，不让 Agent 猜测 |
| 遇到验证码或阻断 | 明确说明并交还浏览器控制 |
| 等待提交 | 完整检查清单和“由我提交”按钮 |

第一版只做“辅助填写、不自动提交”。浏览器控制优先复用用户 Agent 已有能力；网页版若没有安全的浏览器执行环境，先交付申请答案包，浏览器扩展进入 V2.1。

## 10. 主动机制规格

### 10.1 心跳类型

| 类型 | 触发 | 示例 |
| --- | --- | --- |
| 截止心跳 | 投递或材料截止临近 | “岗位明晚截止，当前只缺一条经确认的结果指标。” |
| 面试心跳 | 面试临近且关键风险未训练 | “明天下午面试，最危险的问题还没有完整证据。” |
| 等待心跳 | 超过承诺时间或阶段基线 | “招聘方承诺周三回复，今天可发送一次简短跟进。” |
| 事实心跳 | 关键表述仍待确认 | “简历中的 30% 增长尚未确认来源。” |
| 停滞心跳 | 高价值机会无动作 | “这个机会 5 天未推进，但仍有明确下一步。” |
| 组合心跳 | 多机会资源冲突 | “两场面试相隔 18 小时，建议暂停低价值简历修改。” |

### 10.2 反骚扰规则

- 同一问题在 72 小时内不重复；
- 用户延后后，在约定时间前不再出现；
- 用户静音某机会后，只保留硬截止通知；
- 每日主动问题最多一个；
- 每日行动最多三个；
- “没有值得打扰用户的事”是正常状态。

### 10.3 老师式主动触发矩阵

| 信号 | AI 读取 | 主动提议 | 展开后的动作 |
| --- | --- | --- | --- |
| 新 JD + 有简历 | 要求、证据、历史偏好 | “先判断是否值得投” | 证据化岗位决策 |
| 值得投 + 无岗位简历 | 当前版本、证据缺口 | “现在生成一岗一版” | AI 简历工作室 |
| 简历改动涉及未证实数字 | 来源、版本历史 | “这条数字需要确认” | 单问题补证据 |
| 面试时间进入 72 小时 | JD、简历、历史弱项 | “建议做 15 分钟重点模拟” | AI 模拟面试圆桌 |
| 同一项目连续两次讲不清 | 模拟与真实面试记录 | “项目证据需要一次深挖” | 项目收集 / STAR 训练 |
| 面试结束 6 小时仍未复盘 | 日程、会话状态 | “趁记忆还清楚，记录三件事” | 快速复盘 |
| 等待超过承诺时间 | 沟通、阶段基线 | “现在值得跟进一次” | 生成并确认沟通文本 |
| 多个截止冲突 | 机会价值、时效、耗时 | “今天只保住这一个动作” | 注意力重排 |

每条提议都必须包含：触发原因、读取范围、预计耗时、用户收益、开始 / 延后 / 忽略 / 不再提醒。AI 不得只说“你有一个任务”。

### 10.4 心跳实现

主动性采用“廉价规则监听 + 必要时模型判断”，不能用大模型无休止轮询：

- 网页版：数据库事件、后台队列和定时任务生成候选信号；达到阈值才调用模型；
- Agent 在线版：每次工具执行后检查状态，并在活跃会话中领取本地命令；
- Agent 离线版：每次会话启动先读取未处理信号；
- Agent 主动唤醒：只有用户开启本地守护或宿主定时任务后才启用；
- 通知渠道：先站内，其次是用户主动开启的系统 / 邮件通知。

### 10.5 主动性的学习

系统记录用户对每次介入的 `开始 / 延后 / 忽略 / 静音`。连续忽略同类提议时降低频率；用户常接受的时段、训练长度和表达方式可以成为偏好，但不得从“用户焦虑”推导更激进的催促。

## 12. 可信、安全与伦理边界

1. 任何结论必须可回到材料或用户回答。
2. AI 推断与事实使用不同视觉状态。
3. 用户可以查看、修改、删除证据和历史决策。
4. 自动化对外动作必须在最后一步确认。
5. 不做隐形面试代答或身份欺骗。
6. 不诊断心理健康状态。
7. 不把一次拒绝泛化为用户长期能力。
8. 不把岗位沉默解释为用户失败。
9. JD、网页和附件均视为不可信输入，不能覆盖系统规则。
10. Agent 版默认本地，网页版遵守最小上传原则。
11. AI 只能读取当前动作所需记忆；界面允许查看本次读取范围。
12. 网申自动化默认停在提交前，敏感字段逐项确认。
13. 本地 Agent 未在线时不得显示为正在执行。
14. 主动心跳必须可延后、静音和完全关闭。

## 13. 商业模式假设

### 13.1 免费 Agent 版的作用

- 一句话安装带来低摩擦分发；
- 进入 Codex、Claude Code 和 WorkBuddy 的 Agent / GEO 生态；
- 让高阶用户用自己的模型验证方法；
- 本地作战盘形成真实产品体验，而不是免费提示词；
- 通过匿名、主动选择的产品反馈改进方法，不默认采集求职材料。

### 13.2 付费网页版的付费时刻

优先验证四类付费触发：

1. **重要岗位决策**：用户不想浪费一次高价值机会；
2. **面试临近**：时间有限，愿意为聚焦准备付费；
3. **多岗位失控**：需要持续心跳、跨设备和异步处理；
4. **深度产物**：定制简历、完整模拟与复盘消耗模型成本。

### 13.3 第一付费实验

V2 首先验证“面试关键战役”，而不是同时上线四种付费包：

- 触发：用户将岗位推进到面试，并填写距离面试时间；
- 交付：证据风险扫描、三个决定性问题、一次针对性模拟、一页面试作战书；
- 付费前可看：为什么选这三个问题、预计模型工作与交付边界；
- 付费后衡量：完成率、用户修改率、面后复盘率和再次使用率，不承诺通过率；
- 对照实验：记录“重要岗位深度决策”的付费意愿，作为第二候选，而不是在 V2 首发时分散产品叙事。

### 13.4 不按“焦虑程度”收费

产品不能利用用户恐惧制造强制升级。以下行为禁止：

- “不升级就会错过机会”；
- 虚构倒计时；
- 用低匹配分恐吓付费；
- 把关键事实验证锁在付费墙后；
- 在用户刚收到拒绝时推高价套餐。

付费价值必须是更多模型工作、托管、同步、事件服务和深度训练，而不是解除产品自己制造的焦虑。

## 15. 成功指标

### 北极星指标

> 每周“从不确定转为已完成关键行动”的活跃岗位机会数。

### 激活指标

- 首个 JD 到首个清楚决策的时间；
- 首个担忧被转换为控制地图的完成率；
- 首个高价值问题回答率；
- 24 小时内完成第一项行动的比例；
- Agent 安装到本地作战盘打开成功率。

### 价值指标

- 用户接受、修改和拒绝 AI 建议的比例；
- 决策被新证据合理更新的次数；
- 证据跨岗位复用次数；
- 面试前决定性问题完成训练率；
- 面后 24 小时内结构化复盘率；
- 等待心跳带来的跟进、降级或关闭完成率；
- 用户主动回到同一机会继续推进的比例；
- AI 主动提议被开始、延后、忽略和静音的分布；
- 面试临近提议到完成模拟的转化率；
- 简历工作室产生的建议被接受或有效修改的比例；
- 历史记忆被复用后用户无需重新提供材料的次数；
- Agent 命令领取、完成和失败率。

### 护栏指标

- 未经确认事实进入最终产物的比例，目标为 0；
- 用户报告 AI 内容“不像我”的比例；
- 心跳被静音或判定为打扰的比例；
- 页面给出超过三个同级行动的比例，目标为 0；
- 自动对外动作未确认执行次数，目标为 0；
- 模型失败但扣除额度次数，目标为 0。
- Agent 离线却显示正在执行的次数，目标为 0；
- 不相关历史被错误带入当前岗位的比例；
- 用户关闭主动教练后仍收到普通提醒的次数，目标为 0。

## 16. 端到端验收场景

### 场景 A：看到高价值 JD，但担心背景不够

1. 用户提交 JD 和基础简历；
2. 系统建立要求—证据图；
3. 用户写下“我没有大厂背景”；
4. AI 发现 JD 没有该硬门槛，并连接业务复杂度证据；
5. AI 只追问一个缺失的规模事实；
6. 用户确认后，判断从“补充后投递”更新为“优先投递”；
7. 生成可追溯简历版本。

验收：用户看到判断为什么变化；没有新增虚构经历。

### 场景 B：投递后无回复

1. 用户标记已投递；
2. 系统记录招聘方承诺和阶段基线；
3. 基线前不发送提醒；
4. 超期后建议一次跟进，并给出停止投入条件；
5. 用户发送、延后或关闭；
6. 系统不再制造重复任务。

验收：沉默没有被解释成用户能力问题。

### 场景 C：24 小时后面试

1. 系统读取 JD、定制简历和弱证据；
2. 只选三个决定性问题；
3. 用户进行 15 分钟模拟；
4. AI 追问最危险的一个证据漏洞；
5. 训练结果回写机会；
6. 页面给出两个必须记住的事实，不展示长报告。

验收：用户不需重新解释岗位背景，训练目标来自真实证据。

### 场景 D：面试后反复怀疑

1. 用户提供回忆或转写；
2. 页面分离事实、感受、推断和未知；
3. AI 不猜测面试官决定；
4. 只指出一个决定性优势和一个待修复片段；
5. 生成下一轮训练任务；
6. 本机会进入等待状态。

验收：复盘产生行动，但不把未知包装成失败原因。

### 场景 E：五个机会争夺注意力

1. 系统读取截止、阶段、价值、风险和预计耗时；
2. 今日只突出一个动作，最多列三个；
3. 每项解释为什么现在做；
4. 明确哪些动作被放弃或延后；
5. 用户覆盖排序后，系统记录偏好而不是争辩。

验收：用户能在一分钟内开始行动。

### 场景 F：AI 主动邀请模拟面试

1. 用户为机会录入后天下午的业务面；
2. 心跳发现“定价策略”是 JD 高权重要求，也是过去两次模拟中的重复弱项；
3. 概览右栏出现教练提议，说明为什么现在建议练、读取了什么和预计 15 分钟；
4. 用户点击后，作战盘内展开模拟面试圆桌；
5. 主面试官逐题追问，圆桌在小节结束后讨论；
6. 总教练只留下一个训练动作并回写岗位。

验收：用户没有重新粘贴 JD 或简历；圆桌不在回答过程中制造信息噪音。

### 场景 G：个人 Agent 协助填写网申

1. 当前申请包已确认，Agent 状态显示在线；
2. 用户点击“让 Agent 帮我填网申”；
3. 本地命令进入队列，Agent 领取后打开用户指定页面；
4. 作战盘实时显示字段识别和填入来源；
5. 遇到薪资期望时暂停并向用户确认；
6. 全部填完后停在提交前，由用户检查并提交；
7. 投递结果和使用的简历版本写回机会。

验收：任何对外提交都没有绕过用户；Agent 离线或页面阻断时状态真实可见。

## 17. 交付顺序

### Phase 1：焦虑—证据—行动单岗位闭环

- Concern、Uncertainty、DecisionRecord 数据模型；
- 控制地图；
- 值不值得投 2.0；
- 高价值主动问题；
- 下一最佳行动；
- 一岗一版简历来源。
- 统一 CoachMemory 与 CoachSignal；
- 网页 API 执行器；
- 简历工作室按需入口。

### Phase 2：面试关键战役

- 三个决定性问题；
- 15 / 30 分钟训练；
- 面后事实—推断—未知复盘；
- 训练结果回写。
- 旧六角色圆桌迁入岗位工作空间；
- 主面试官与圆桌分阶段呈现；
- 面试临近主动提议。

### Phase 3：等待与心跳

- 阶段等待基线；
- Follow-up；
- 停止投入条件；
- 反骚扰机制。
- Agent 命令队列与在线状态；
- Level 0 / Level 1 互联。

### Phase 4：多岗位注意力

- 今日注意力预算；
- 组合风险；
- 用户覆盖与长期偏好；
- 跨机会证据学习。

### Phase 5：可观察的网申协作

- 浏览器控制能力检测；
- 字段映射与答案来源；
- 实时动作日志；
- 敏感字段确认；
- 提交前交还用户；
- 失败时申请答案包降级。

## 18. 发布门槛

- 至少 8 位真实求职者用自己的材料完成单岗位闭环；
- 至少覆盖在职跳槽、失业求职和应届求职三种状态；
- 用户能在 60 秒内说清楚当前判断、最大未知和下一步；
- 所有最终简历新增事实可追溯；
- Agent 版从一句话到本地作战盘的成功率达到可用门槛；
- 网页版模型消耗有明确展示和失败不扣费；
- 主动心跳支持延后、静音和关闭；
- 七个验收场景全部通过；
- 桌面和移动端无关键能力缺失；
- 不发布未经验证的成功率、Offer 概率和用户背书。

## 19. 已确认与待确认决策

### 已确认

- 岗位机会仍是唯一主线；
- 网页付费版与本地 Agent 免费版分别闭环；
- AI 产物必须可追溯；
- 聊天只承担输入、确认和状态通知；
- Agent 必须操作可见作战盘；
- 主动提问和心跳属于核心能力；
- 不做自动海投和隐形面试代答；
- 免费 JD 决策负责激活，面试关键战役作为第一付费实验。
- 旧简历双 HR 和面试六角色能力返场，但只在对应任务中按需展开。
- 一个 AI 教练贯穿所有岗位阶段，使用检索式长期记忆。
- 主动性是核心产品能力，不是通知附属功能。
- 网申第一版只辅助填写并停在提交前。

### 待确认

1. 用户担忧是自由输入为主，还是先提供 4 个可选入口；
2. 等待基线采用统一规则还是按岗位阶段学习；
3. 网页版免费层允许保存几个岗位；
4. 面试战役采用单次购买、点数包还是包含在短周期订阅中；
5. 浏览器 Clipper 是否与网申扩展合并；
6. 本地 Agent 版未来同步到云端的授权和冲突策略；
7. 各宿主 Level 1 在线互联的最低可靠性门槛；
8. “项目深挖”独立工作空间的首版输入方式。
