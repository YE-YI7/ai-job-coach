# 爱猹收积分入口 UI 复核（2026-10-09）

## 结论与边界

本次是既有作战盘的支付积分入口扩展，不是新视觉世界、套餐营销页或全站重设计。现有 `PRODUCT.md`、`DESIGN.md` 和系统 sidecar 保持不变；此处只记录局部组件及其验收边界，不把一次支付组件评审升级为全产品认证。

当前证据支持：实际 `WatchaPayWidget` 在本地合成数据夹具中能以桌面、窄桌面和手机布局呈现清晰的余额、购买、刷新和兑换顺序。没有正式生产页面视觉验收，也不代表真实付款、到账、交付、退款或对账完成。

## 既有系统的延续

组件继续使用暖纸底、深墨正文、暖灰细边界和橙色行动。继承的值包括纸底 `#fbfaf8`、正文 `#24272f`、边界 `#e7e5e1`、白色表面与悬停栏底 `#f7f5f1`。按钮采用既有控件圆角（10px），对话框采用既有容器圆角（16px），字体沿用作战盘中文无衬线栈，没有新字体、插画或装饰图像。

主动作局部采用既有公开路由深行动橙 `#b94719`，悬停进一步加深为 `#983a15`；说明文字 `#626772`、成功文字 `#216747`、错误文字 `#8f3424` 是支付表面的局部高对比色调，并非新的全局语义色或规范 token。成功、错误、加载均带文字，不只用颜色区分。焦点使用偏移的 2px 说明灰轮廓，保留清晰键盘识别；这是局部实现，不改写全局橙色焦点规范。

余额的 48px 等宽数字只承担数值扫描，标题 18px、商品标题 15px、说明 13px。该局部数值强调不把作战盘升级为超大标题营销页面。

浮层通过真实 modal 背景遮罩建立层级；内部以横向细线分区，不套多层卡片，不引入渐变、光斑或玻璃效果。购买和兑换分属两步动作，不把渠道余额直接当作益职可用余额。

## 交互、同意与隐私

- 原生 `<dialog>` 具有标题关联；关闭按钮有明确标签、初始焦点。Escape 与焦点行为由原生 modal 机制提供，主阵已报告测试完成。
- 每次重新查询、打开窗口、关闭窗口或成功兑换都会清除勾选同意；用户必须再次确认渠道兑换后的原路退款边界，才可主动兑换。
- 查询和兑换期间显示“查询中…”或“处理中…”，刷新、勾选和兑换暂停，关闭按钮保持可用。余额未首次返回且无错误时不显示入口；未配置时隐藏；查询失败保留重试入口。
- 待确认兑换以文字提示“可安全重试”，动作改为“继续确认兑换”；这只是可见交互契约，服务端幂等与真实恢复须由独立业务测试证明。
- 未授权 demo 数据不展示此支付入口；真实作战盘入口与 TokenPay 并存，说明明确写出 TokenPay 优先，不替换其余额语义。
- 浏览器只调用本产品钱包接口，兑换请求只发送 `confirmExchange: true`；组件没有读取或发送简历、JD、面试材料。购买链接打开渠道页面，采用 `noopener noreferrer`；可选渠道二维码图片采用 `no-referrer`。二维码仍会请求其图片来源，不能据此宣称没有第三方网络请求。
- 无新生成视觉资产。可选二维码是运行时渠道数据，不是本轮生成或静态交付的品牌素材；三张合成截图未显示二维码，不能作为扫码路径验收。

## 响应式与验收范围

对话框最大宽度 440px，横向至少预留 32px 视口余量；最大高度按 `100dvh - 32px` 限制并允许内部滚动。480px 以下内边距降为 20px。检查的手机截图中购买、刷新、关闭和兑换均可见，退款说明自然换行，没有横向溢出；桌面和窄桌面保持同一阅读与操作顺序。

本轮单次扫描已结束，不重复扫描未修改的历史问题。新增局部色调和数值字号无需扩大为系统重构；未来若将其复用到多个表面，应另行确认是否提升为规范 token。

仍需分别验收：生产登录作战盘实际集成、真实配置下的 loading/error/unavailable/pending/成功状态、二维码显示与扫码、真实付款后余额回读，以及业务交付和退款/对账。合成夹具不覆盖生产账号、密钥、渠道准入或真实资金，当前不作生产视觉通过结论。
