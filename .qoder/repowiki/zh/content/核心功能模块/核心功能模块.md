## 用户注册与认证流程

用户从注册到进入主界面的完整流程包括：注册页面提交信息 → 邀请码验证 → 创建会话 → 加载用户状态 → 进入主界面。系统基于Supabase进行身份认证，通过`getCurrentUserFromRequest`函数从请求中提取当前用户信息。

## 邀请码系统实现

邀请码系统通过`/api/invites/check`接口实现验证功能，支持GET和POST两种请求方式。该接口检查邀请码的有效性、使用状态、过期时间及剩余使用次数，并返回详细的状态信息。

```mermaid
flowchart TD
Start([开始]) --> ValidateInput["验证输入参数"]
ValidateInput --> InputValid{"参数有效?"}
InputValid --> |否| ReturnInvalid["返回无效参数错误"]
InputValid --> |是| QueryDB["查询数据库"]
QueryDB --> DBResult{"邀请码存在?"}
DBResult --> |否| ReturnInvalidCode["返回邀请码无效"]
DBResult --> |是| CheckUsed["检查是否已使用"]
CheckUsed --> Used{"已使用?"}
Used --> |是| ReturnRedeemed["返回已使用状态"]
Used --> |否| CheckExpired["检查是否过期"]
CheckExpired --> Expired{"已过期?"}
Expired --> |是| ReturnExpired["返回已过期状态"]
Expired --> |否| CheckRemaining["检查剩余次数"]
CheckRemaining --> Remaining{"有剩余次数?"}
Remaining --> |否| ReturnNoUses["返回使用次数用完"]
Remaining --> |是| ReturnValid["返回有效状态"]
ReturnInvalid --> End([结束])
ReturnInvalidCode --> End
ReturnRedeemed --> End
ReturnExpired --> End
ReturnNoUses --> End
ReturnValid --> End
```

## 简历上传与解析机制

简历上传功能通过`/api/resume/upload`接口实现，支持PDF、DOC、DOCX格式文件。系统使用formidable库解析multipart/form-data，将文件存储至Supabase Storage，并在数据库中记录元数据。

简历内容提取通过`/api/parse-resume`接口实现，采用`pdf-parse`库解析PDF文本，再通过LLM进行结构化信息提取。技术路径如下：

```mermaid
flowchart LR
A[上传简历文件] --> B{验证文件类型}
B --> |PDF/DOCX| C[解析文件内容]
B --> |其他| D[返回错误]
C --> E[提取原始文本]
E --> F[调用LLM进行结构化解析]
F --> G[返回JSON格式数据]
```

## 多阶段AI引导流程

系统采用状态机模式管理用户求职流程，定义了七个核心阶段：职业规划、项目梳理、简历优化、投递策略、模拟面试、薪资沟通、Offer评估。`lib/stage.ts`文件中定义了`UserStage`类型和阶段跳转逻辑。

```mermaid
graph LR
A[career_planning] --> B[project_review]
B --> C[resume_optimization]
C --> D[application_strategy]
D --> E[interview]
E --> F[salary_talk]
F --> G[offer]
```

每个阶段由对应的AI代理处理，通过`getNextStage`和`getPrevStage`函数实现阶段跳转。系统根据当前阶段提供相应的引导内容和交互界面。

## 模拟面试系统生命周期

模拟面试系统包含三个核心接口：`/start`触发面试、`/answer`接收回答、`/assess`生成评估。其生命周期如下：

```mermaid
sequenceDiagram
participant 用户
participant 前端
participant 后端
participant LLM
用户->>前端 : 开始模拟面试
前端->>后端 : POST /api/interview/start
后端->>后端 : 创建会话记录
后端->>LLM : 生成面试题
LLM-->>后端 : 返回问题列表
后端->>后端 : 保存问题到数据库
后端-->>前端 : 返回会话ID和问题
前端-->>用户 : 显示第一个问题
用户->>前端 : 提交回答
前端->>后端 : POST /api/interview/answer
后端->>后端 : 验证会话权限
后端->>LLM : 评估回答质量
LLM-->>后端 : 返回评估结果
后端->>后端 : 保存答案和评估
后端-->>前端 : 返回评估反馈
前端-->>用户 : 显示评估结果
```

## 白板持久化机制

白板数据通过`/api/save-whiteboard`和`/api/load-whiteboard`接口实现持久化存储。系统使用Supabase数据库的`whiteboard_states`表存储用户白板状态，以用户ID为键进行upsert操作。

```mermaid
flowchart TD
A[用户编辑白板] --> B[触发保存]
B --> C[POST /api/save-whiteboard]
C --> D[验证用户身份]
D --> E[写入数据库]
E --> F[返回成功]
G[用户进入页面] --> H[POST /api/load-whiteboard]
H --> I[验证用户身份]
I --> J[查询数据库]
J --> K{数据存在?}
K --> |是| L[返回白板数据]
K --> |否| M[返回空数据]
```

## 会话恢复机制

会话恢复通过`/api/load-session`接口实现，该接口验证用户身份后返回用户基本信息，用于恢复前端会话状态。系统依赖Supabase的认证机制，通过`getCurrentUserFromRequest`函数获取当前用户。

```mermaid
flowchart TD
A[前端请求会话] --> B[POST /api/load-session]
B --> C[验证认证状态]
C --> D{已认证?}
D --> |否| E[返回401错误]
D --> |是| F[获取用户信息]
F --> G[返回用户ID和邮箱]
G --> H[前端恢复UI状态]
```
