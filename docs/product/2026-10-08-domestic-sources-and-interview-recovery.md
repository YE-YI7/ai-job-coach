# 国内招聘源扩充与面试恢复修复

## 已实现

- 产品运行时国内官网查询由腾讯、网易扩到六源：新增百度社招、美团社招、京东应届生、快手校招/实习。不是开发时抄一批岗位，也不是只有公司名单。保留 Exa 跨公司发现，非互联网行业不被禁用。
- 每源一次隐私闸后的关键词查询，并发 3；先覆盖所有源，不因旧 `maxCalls=4` 静默截掉新公司。公开搜索另有 2 次检索、1 次批量读取，总出网预算 9。产品经理方向用过闸的岗位别名召回，后续简历、专业方向、地点、硬门槛及引用核验不移除；评审仍最多一轮，最终最多 5 条、首屏 3 条。
- 新源保留原页 ID、国内地点和完整职责/要求；海外、失效、地点不明、非法 ID 丢弃。京东和快手的校园来源明确标注，不能当社招覆盖。更新时间不伪装发布时间。
- 更新来源版本，旧双源任务不再冒充当前资料对应的新搜索结果；读取旧结果仍不会自动发起收费搜索。
- 面试持久化记录恢复时转换成可渲染视图，不再 `as unknown as` 强转。数据库记录确有旧评价缺少 `variance` 和旧总结缺少可选数组；历史点评的 `scoreBandShort/Line` 原来会解引用不存在的字段。现在补安全的空列表与“未实测”说明，不补造分数或事实；原始持久化数据未修改。已有真实测量说明在再次恢复后保留。

## 实测与边界

- `JOBS_SOURCE_SMOKE=1 npm test -- --runInBand lib/jobs/domestic-sources.live.test.ts`：真实官网关键词“产品”，腾讯 40、网易 40、百度 20、美团 38、京东 5、快手 40，共 183 条国内候选；6 次请求、失败 0，约 0.84 秒。这是来源取数，不是183条推荐，也不是收费模型端到端验收。新四源正文长度、来源 URL 和国内地点断言通过。
- 百度首次运行时验收暴露缺少公开 POST 的同源上下文，返回 `no-auth/illegal-visit`；补官方请求的 Origin/Referer，保留益职自己的 User-Agent，不伪造浏览器、不借用户 Cookie、不解验证码。真实重跑通过。
- 字节官网公开请求当前返回 405，未冒充接通；阿里、滴滴、小红书、B站、小米等直连源本轮尚未实现。Exa 可以发现其公开索引，但不等于逐家公司已验收或全市场覆盖。
- 面试复验依据为只读数据库结构统计、缺字段的原始渲染错误复现、恢复测试和类型检查。浏览器连接连续超时，本轮未完成真人账号点击复验，不把代码测试当成真人签收。
- 余额：已核查刷新时的聊天读取、模型目录、余额查询、公司研究和触达提示。研究 `modelCalls=0`；触达提示是规则生成，点击才发送付费导师请求；余额 GET 读取 TokenPay余额并同步本地记录。未发现这些读取入口调用付费模型。没有 Kimi 此次 reload 的精确时间/请求账单，不能证实该一分钱由刷新造成，也不能排除其他并发调用或上次使用余额回显更新。本轮未更改价格、授权、充值或登录滑块。
- 本轮 UI 仅改面试记录恢复接线；手动 Impeccable detect：0 anti-pattern、7 advisory；不扩大旧界面问题，不开启钩子。

## 不包含

首页定位重写、状态语言统一、单一下一步聚合、移动端重设计及登录链路改造未在本轮混入。每日就业市场 cron 不是每日招聘源扩展，不能将两者混说。仍需逐家扩充、核验国内招聘来源；本轮没有声称“大厂全部接通”。
