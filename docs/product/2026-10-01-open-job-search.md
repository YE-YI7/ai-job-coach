# 跨公司、跨行业运行时找岗

## 用户目标与实现

上传简历并保存方向/城市后，益职自己发现公开招聘页。无需开发者预先登记每家公司，更不把固定两家公司当作整个市场。

主链路：隐私闸后的方向/技能与受控城市 → 两个公开网页搜索 → 发现链接、排除列表/资讯/匿名猎头 → 批量读取最多八个详情 → 抽取有出处的公司、岗位、地点、职责及要求 → 合并官网补充源 → 去重、已跟踪排除、方向/地点/学历/年限筛选 → 一次基于用户经历的私有模型评审 → 最多五条，附原文引用、差距、小练习 → owner 隔离保存与回读。

Exa hosted MCP 是产品服务器直接 HTTP 调用，不依赖 Codex 桌面、开发者手动点击、用户 Cookie 或固定企业网址。腾讯/网易只是并行补充源。机械、电气、会计、护理等方向也能提交搜索；没有把行业限制为互联网。岗位资料不作为可执行指令。无法识别雇主、地点或职责/要求的页面不猜测、不用搜索摘要冒充已读取详情。

## 预算、缓存和失败

- 两次搜索、一次批量页面读取，加两关键词 × 两官网，最多七次网络请求，零搜索规划模型调用；每次搜索/读取超时十二秒、响应一 MB 上限，无自动重试。
- 硬筛后的评审最多十六候选，按公司轮转分配候选预算，防止单公司大量结果淹没其他公司；不强制最终推荐公司配额。每条 JD 摘录最多一千字符、简历六千字符、输出一千四百 tokens，最多一次模型调用。
- 三十分钟共享缓存只存公开结果；键是已过闸词和受控城市查询，不放简历正文或用户自由地点文本。失败/缺页不锁入共享缓存，原有保存结果和个人记忆仍 owner 隔离。
- 搜索源失败和无匹配岗位分开；跨公司搜索受限时如实显示该源失败，不能称全网已搜。模型或保存失败退益职预留额度，不返回伪个性化成功。
- EXA_API_KEY 可选；无 key 使用服务公共配额，可能受限，不承诺无限免费或生产 SLA。需要持续规模化时应配置自有搜索服务配额，不在本轮擅自购买。
- 不绕过登录/验证码，不代投。搜索服务返回的页面可能为缓存索引，抓取时间不等于在招证明。无明确发布时间保留待核实；招聘页项目实际地点优先于标题城市，未知地点不编造。

## 已观察的验证

运行时源探针 `scripts/verify-open-search.mts` 真实调用两次搜索与一次批量读取：上海机械方向找到梅卡曼德、中建材凯盛机器人、上海之江生物、上海伟矩、施耐德、发那科、果栗智造、它石智航等；北京 AI 方向找到中移九天、理想汽车、诺禾致源及万联易达。不是手工写入的企业列表，原 URL 和读取内容保留在 `/tmp/yizhi-open-search-live.json`。

首次会计探针为空：多数来源匿名或无法确认雇主；没有把这些页面当成岗位填数。改进详情读取前候选优先级、排除匿名猎头后，找到一条可归属的阿里财务岗位。仍不据此称会计覆盖充分。实测还发现杭州标题下项目地点为福建武夷山，已增加回归测试，不按杭州匹配。

自动测试覆盖：非互联网动态查询、地点隐私、不安全 URL、SSE/JSON、受限失败、搜索→动态 URL→批量读取、跨页归属、匿名/缺资格/关闭/列表剔除、地点冲突、实际 route 接线、取消/重放/回读、机械不误召回软件、跨公司评审预算。
