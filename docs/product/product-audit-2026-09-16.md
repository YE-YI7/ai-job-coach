# 益职 AI：使用数据与求职者体验审计

日期：2026-09-16。结论：已有可用的辅导与记忆基础，但事实可靠性和功能衔接不足，适合小范围陪跑内测，不宜以“完整主动求职导师”大规模推广。

## 范围与证据边界

- 生产数据库只读聚合：北京时间 9 月 14 日 17:43 至 9 月 16 日 17:43（滚动 48 小时）。数据先取样，再进行合成测试。
- 生产正式 API：临时虚构应届生账号，连续两轮辅导、历史回读、归档、新会话读取记忆；完成后删除测试账号。没有改动真实用户资料。
- 本地实际浏览器：当前分支桌面 1440×1000、手机 390×844，面试、长简历、复盘界面。不能冒充生产登录态全流程验收；PDF 真正导出、实时语音、真实录音上传及谈薪交付本轮未签收。
- 代码审计及检索/规划测试：3 套件 115 项通过。未修改产品代码、未部署。

## 合成求职者线上实测

输入事实仅有：应届、没有实习、会议摘要课程原型、访谈 3 个同学、未上线。先问 5 年经验岗位是否适合，再要求真实简历描述和当天评测练习。

| 请求 | 首个文本 | 全部完成 | 记录的模型耗时 | 输入/输出 token |
| --- | --- | --- | --- | --- |
| 岗位判断与学习建议 | 8.150s | 11.915s | 2.902s | 1695 / 356 |
| 简历描述与评测练习 | 5.619s | 9.440s | 3.734s | 2049 / 483 |
| 新会话接着学习 | 6.572s | 9.302s | 2.082s | 1751 / 131 |

均走托管 Flash，单轮 modelCalls=1。这些是本机网络下正式 HTTP 流式调用耗时，不是总体 p95。端到端耗时明显高于模型日志，需为鉴权、上下文装载、首字、写回分别打点，当前不能武断定位某个步骤。

有效帮助：正确识别 5 年经验为硬门槛；给出三段文本、每段三个必保留要点、检查遗漏和编造的具体练习；历史回读 2 轮成功；归档后新会话读到了未完成练习。

### P0：简历事实被补写

模型声称只用确认事实，却写入“归纳高频需求、梳理核心流程、可点击原型、向同学演示并按反馈调整”等未被用户提供的动作。没有虚构数字不等于没有虚构经历。

修复验收：最终简历每个事实性分句绑定用户原话或确认事实 ID；新增动作只能列为待确认问题。加真实模型反例评测，而不只是检查 prompt 包含“不编造”。

### P0：归档把讲解记成掌握

用户没有提交答案，归档却写“已验证掌握点：能区分……理解 5 年经验客观硬门槛”。系统 prompt 已要求不要这么做，但没有结构化校验。错误会作为长期记忆进入后续辅导。

修复验收：分别记录 taught / attempted / demonstrated；demonstrated 必须附用户作答 turn ID 和判断依据。没有作答就只能记录“已讲解、待练习”。

## Harness：有基础，但不是结果闭环

- Context：历史摘要、用户事实、岗位材料、检索正文和预算裁剪已接入；本次知识 ID 可追溯，不是空壳 RAG。
- Memory：数据库保存档案快照、对话与学习摘要；并不需要每用户常驻计算沙箱。手动归档后跨会话读取成功；“新辅导”不会自动总结上一轮，连续积累有断点。
- Retrieval：文档编译成 JSON，以词项/标签/任务筛选；测试覆盖 Top-3 命中与话题延续。实际辅导最多取 2 篇，不能把 Top-3 测试直接当线上 Top-2 效果。第三轮召回偏泛，但读到了学习记忆。
- Loop：辅导是单次模型调用加有限超时降级，没有“发现证据不足→再检索→验证建议”的结果闭环。简单问题维持单次调用正确；只对证据不足/冲突启用最多一次补检索，避免空转烧 token。
- Evaluation：115 项通过主要证明固定检索与规划规则，没有覆盖真实输出的事实支持、练习可完成性、错误掌握归档。新增上述两个反例为上线门槛。
- Trace：有知识 ID、模型、用量、上下文指纹；缺全链路耗时分段、最终事实支持与用户采用/学习结果。
- 心跳：每天抓固定就业来源；本次只有国家统计局列表页更新。不是用户级主动导师，也未证明细分岗位趋势判断。需要先做面试临近/练习未完成等确定性事件提醒，再按需调用模型；不要每人定时空跑模型。

## UI 与交互

1. **P1 桌面主按钮不推进**：面试中栏“开始第一次练习”只设置 mobileRail，桌面右栏本来已显示，实点无可见进展。应直接打开首题并聚焦答题位置。
2. **P1 错误完成态**：InterviewStageOverview 无题时 priorityFocus 为空，也显示“当前重点题已准备完成”。待生成、缺材料、完成必须分开。
3. **P1 工具与导师割裂**：进入面试阶段会隐藏聊天、整栏改为面试工具。用户此时无法就题目继续问导师；应保留同一会话，题目卡作为会话关联工具。
4. **P2 视觉重复而非缺装饰**：大块深色中栏头图、重复的重点题、右栏另一套标题和开始按钮抢主次。中间应只显示当前题/进度/已保存反馈，右侧承担唯一练习动作。
5. **P2 移动端发现成本**：390px 无横向溢出，但阶段轴一屏只见部分阶段，聊天靠顶栏图标打开；长简历下要滚很久。需要明确的“问导师”入口、当前阶段锚点和可见的水平可滚动提示。
6. **P2 复盘仍以大文本输入为主**：轮次可选，但本次界面没有就地音频导入入口；与用户“交材料即可开始”的预期仍有距离。

## 建议实施顺序及验收

1. 先修事实生成与记忆污染：最小事实输入不能出现额外经历；无作答不能记已掌握；三次新会话读取保持一致。
2. 修主按钮和面试/聊天衔接：桌面及手机一次点击进入首题；无题不显示完成；就题追问、回答、点评、重答、保存和刷新回读形成一条链。
3. 分段延迟与低成本优化：先打点，再并行独立加载和按版本缓存稳定档案/知识；区分首字延迟与生成速率。建议目标首字 p95 < 5 秒，属于目标而非当前成绩。
4. 最后做 5 名目标求职者陪跑：每人真实岗位，从材料到一份采用的简历和一次保存的面试改进。记录是否独立完成、哪里求助、输出是否采用，而非只问好不好看。

本次结论不等于上线验收。优先修 P0 后再增加推广流量；暂不继续堆新模型、沙箱和装饰。
