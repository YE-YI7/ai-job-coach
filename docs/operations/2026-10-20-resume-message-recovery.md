## 修改

1. 每条失败消息保存安全错误类型/短恢复说明；允许采集的账号附本次真实 Trace ID。不存原始供应商错误或秘密。
2. 失败响应携带当前任务回执；前端先接收回执再提示失败，避免依赖4秒轮询恰巧先返回。
3. 每条失败消息直接“重新发送”；复用原消息 ID，去重、不重复记录。输入区重新发送相同文本也复用失败 ID。成功回执只清空对应草稿，不能清掉另一条未发送消息。
4. 最新消息失败/等待/讨论时，不再重复展示旧任务的改稿失败或成功提示。保持本人要求的聊天气泡、原字体与输入位置。
5. 刷新时恢复服务端 pending 并继续只读轮询；90秒过期才允许接续，服务端 CAS 阻止迟到响应覆盖新请求。
6. 导师改为内部接收上游流，完整结束后才解析 JSON / 保存决策 / 触发原编辑。45秒总期限、30秒首活动期限，无自动模型重试、无提供方切换、无预算扩大。该传输调整减少网关等待完整响应的需要，不宣称消除供应商自身超时。
7. 已保存的导师决策仍重放而不重复模型；后续编辑/结算异常仍回外层完成原租约清理。
