# 已保存岗位无法进入导师上下文

## 根因与修复

- 原路径只读取当前 opportunityId，用户在其他工作区提到左侧已保存岗位时无法解析。新增 owner + active 范围的轻量名称查询（最多100条，与岗位列表上限一致），唯一明确匹配才加载对应 JD、事实与面试记录；多个候选要求确认。不模糊猜测公司别名。
- 原 prompt 把已保存材料放在可选历史之后，可能被预算截断。现在优先装入预算已校验的证据包，历史摘要后置，总预算仍为8000 token。不增加模型调用。
- 不迁移原对话会话、不跨岗推进阶段；引用另一岗位也校验原工作区 owner，避免通过引用绕过鉴权。

## 验证

93套、796项测试通过；类型检查、生产构建通过。覆盖截图原句、同公司多岗歧义、所有者隔离、原工作区权限、上下文加载岗位与对话存储岗位分离、长历史不挤掉优先材料。
真实账号复现与供应商返回内容本轮未验收，不以单元测试替代模型效果。

## 找岗边界

现有基础档案找岗仅 Meshy/Kong 两个公开来源，按保存方向/城市筛选，再按简历关键词排序；不是模型全网找岗，未接入聊天工具，未新增国内来源。此次修复不扩大该能力。
