# 简历编辑合同与独立质检

本页仅说明通用工程边界。用户材料、案例指标、Trace编号、节点I/O与实测费用应保存在已有管理员Eval，不作为公开仓库的测试附件或业务成绩。

## 执行合同

- 用户已确认的修改要求与经历事实分开；最新方向决定当前目标，历史方向只作背景。
- 成熟简历默认保留结构。仅在明确授权、短单项目口述、无身份信息/多章节时允许原子重组；单段体验及收费范围不扩大。
- 原子编辑目标由服务端绑定，模型不需要复抄整段原文；未知目标、错误原文、越界修改均不能静默修正后放行。
- 主线编辑须体现内容取舍与具体贡献，不能只换词、删领头或将纠错标为内容优化。编辑计划只记录可检查的简短取舍，不要求隐藏推理。

## 独立复核与返修

- 编辑、确定性事实/定位/格式守卫、独立整稿检查和有界返修沿用现有链路，不新增常驻Agent。
- 日期的等价格式可归一，但数值、量纲、日期精度和事实来源必须保持。结构编号不是业绩数字；有后续正文的短标题不等于半句，真正悬挂结尾仍须拦截。
- 明确修改要求必须有独立的覆盖判断。缺少覆盖字段是协议错误，不可直接默认为完成或把系统错误归咎于用户。
- 同一候选补全质检协议时，已有明确否决、负价值判断和未完成要求不能被清除；未可靠定位的明确否决也不能变成通过。正文问题退回原编辑处理。
- 用户材料保留自述级别，知识只提供方法，不成为履历事实。没有JD不展示无依据的ATS满分。
- 不能因数字有来源就认可整句：优化目标、方向性标题不等于已取得的新定性收益。总领与条目重复同一痛点和功能也需检查，结构完整不是内容质量的替代品。
- 退回原编辑时保留上一版候选与具体反馈；独立复核逐项核对未解决问题。上一版模型文本只是待修候选，不进入事实来源。

## Eval与发布边界

- 管理员显式确认费用的隔离样本不能带入旧岗位ID、任务租约、旧作答或真人额度逻辑；普通产品接口不能接受这些服务端执行开关。
- 隔离Eval的同流程返修须读取本人所属父记录，锁定同一原材料、初始要求和模型；父子调用共用原上限。固定派生的续接编号在调用前持久预留，只允许一次续接，不能把返修变成无限新开流程。人工验收反馈必须标明来源，不能伪称原自动质检已经识别。
- 同稿同模型对照要实际传递同一要求，保留全部调用和失败。记录实际参数、Token、耗时与价格依据；没有账单时费用只能标估算。
- 回放、单元测试、构建、真实模型验收和正式发布是不同状态。代码检查通过不等于内容质量通过；候选没有通过质量准入时，不切正式域名。
- 数据保护通过原稿、作答、积分和既有证据的前后核对验证，不以“没有主动点击保存”代替检查。
