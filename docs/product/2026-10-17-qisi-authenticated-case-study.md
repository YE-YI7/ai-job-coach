日期：2026-10-17。范围：参考研究，不是 UI 实装、审美签收或新一轮功能验收。

## 研究证据与边界

- 使用用户已登录的 Codex 内置浏览器；账号菜单可见，详情可打开。另开同浏览器研究标签，未导出 Cookie、另行注册、收藏作品或上传用户资料。

## 3. 三个转换的进一步检查

1. **文件夹收回，约 2–4s。** 8fps 连续帧能看到表面缩小、下移、背景逐步恢复；不是“详情直接消失，再淡入列表”。借鉴目标是同一个对象的往返和焦点恢复，不是添加一个缩放动画就算完成。
2. **Agent 归档，约 8–10s。** 父任务最后一个子项完成，组状态变更，进行中计数减少、已完成计数增加；组移动时其他内容重新排布。益职应保留“本轮改了哪段”的归属，完成后进入可检查的结果；不能只把忙态文字替换成一句完成。
3. **文件完成，约 11–13s。** 成功标识、状态文案、进度条收束、后续动作展开不是同一帧同时出现。可借鉴主次顺序，但其网络进度为演示，不能用于决定真实保存成功的时机。

## 4. 给益职简历板块的具体设计约束

这些是下一次实现的候选契约，**不是本轮已经完成的功能**。保留用户认可的左侧两分区，不重做全站。

### A. 阅读态：先看到完整作品

- 简历纸面是主视觉；普通阅读不铺区块边框、虚线、常驻编辑按钮和多段说明。
- 纸面、应用背景、临时工具应有可分辨的表面深度。不能为了“极简”把必要层次全部抹平，也不能只换背景而保留密集后台布局。
- 姓名和联系方式、原件与新稿的身份要稳定；未经用户确认不因套模板改掉原件样式。

### B. 选中/编辑态：动作靠近对象

- 当前段落才显现编辑/更多入口；工具条标明作用对象，保持与选中范围的对应。
- 编辑在原位置展开，不另开一张大编辑卡；编辑时入口不会因移出 hover 而消失。
- 菜单的边、阴影、行高、图标重量、内外圆角成套处理。危险项有区分，不把所有动作都做主按钮。
- 键盘焦点、触屏点击和点击空白收起都要可用；保存失败时不能由浮层关闭造成输入丢失。

### C. Agent 处理/补问态：系统状态与用户任务一致

- 区分“文件已上传”“正在读材料/改稿”“需要你补一条事实”“新稿已生成”“正在保存”“已保存”。阶段文案必须由真实服务端状态支持。
- 进度就近附着当前文档/区块；不在中心叠一排阶段卡，不展示内部子 Agent 和给负责人的 Trace。
- 补问只出现当前问题；原简历和已完成修改继续可读。用户不补充时，已足够的事实照样可改。
- 长等待不能伪装成持续增长的完成百分比；超时留住材料和重试入口，不为了演出顺滑将未保存结果当成成功。

### D. 采纳/保存/导出态：变化结束后交还阅读

- 接受修改后只让当前修改标记收束，文字与阅读位置保持稳定；三色是待评估机制，不是已确认的审美偏好。
- 云端确认前明确“未保存/保存中”；失败在原位置提供重试并保留本次输入。刷新恢复以真实持久化为验收依据。
- 删除有可理解的对象、确认和撤销，不使用“永久删除但五秒可撤销”的矛盾表述。
- 导出确认只在确有未决修改时出现；PDF 以干净成稿和原有排版契约为准，编辑标记、菜单、状态提示不能进入纸面。

## 5. 下一轮实现应怎样验收

1. 同一份虚构简历录制阅读→选中→编辑→补问/继续→采纳→保存完成的连续路径；看焦点、对象身份与位置，不用几张静态截图拼成“流畅”。
2. 分别录制云存成功、失败保留、重试成功；只有后端确认后进入成功状态，刷新后核对同一版本。
3. 桌面 hover、键盘和手机触屏使用相同任务路径；低视口下菜单不盖住正在输入的内容。
4. 检查 reduced-motion：取消非必要位移/缩放仍能识别所选对象、处理中、失败与完成。
5. PDF 实际生成、解析、逐页渲染；检查一页优先、身份信息、长行、项目分段和无编辑控件残留。
6. 若进入 UI 修改，再按仓库规则对本次文件集中运行一次 Impeccable detect，必要修复后最多一次复核。当前只有研究文档，不扫描历史 UI。

本轮未改运行代码、生产数据、余额、原件或旧作答；未部署，也未重新做真实模型、云存刷新或 PDF 验收。此前功能验收与本轮研究分开记录，用户审美认可仍以实际反馈为准。

### 6.3 这轮补上的设计判断

1. **轮廓不只是一条 border。** 细亮边、局部暗沿、表面弧度、背景透色共同决定是薄片、软胶还是厚工具。先确定一种材料，再统一其边缘表现。
2. **投影有两种作用。** 紧贴物体的暗部交代接触和重量，外扩的柔影交代与背景的距离。纸张与浮动菜单的投影不能只是复制同一个 `box-shadow`。
3. **质感来自对照。** 光滑工具、平整纸面、安静背景可以有差异；处处同样模糊、同样颗粒或同样高光，会丢失主次。
4. **纹理应服从形体。** 颗粒、网点、纤维、拉丝并非同一种东西；它们的尺度、方向与受光也不同。不以一层全屏噪点替代所有材料。
5. **灰色与彩色都要完整。** 硬件组说明灰色也需要丰富的局部明暗；毛毡与空间光说明彩色可以很精致。不能把“高级”简化成去色，也不能把彩色 blob 当完整主视觉。
6. **材质不吞掉文字。** 表面可以透、粗糙或反光，阅读与操作文字仍需清楚；图标粗细、字面重量、内边距和轮廓曲率要一并判断。
7. **运动时也维持材料身份。** 纸张的弯曲、玻璃的透色、轻工具的展开不是一个通用弹跳效果；日常编辑可以只借其连续性，不为表现材料增加等待。

### 6.4 益职的候选落点，不是新一轮视觉批准

- **简历纸面：** 稳定、清晰、平整；屏幕只在边缘表现薄纸和离底面的距离。原件不重新排版，材质不进入 PDF，不用做旧颗粒覆盖用户文字。
- **简历工具：** 以细腻轮廓、局部明暗和一致的几何关系产生触感；普通工具保持轻，少量主要动作有更明确的表面与重量。先做一组阅读/选中/展开/按下的连续状态，再判断是否成立。
- **介绍页：** 可以更鲜明、更有颜色；优先围绕一个真实作品或原创主视觉组织材质、光线和构图，不在空白背景上再堆组件与图标。
- **保留边界：** 左栏不重做；本轮只补研究，没有改品牌令牌、全局字体、业务调用、用户事实或旧作答。以上需实际渲染和用户视觉反馈后再决定，不写成新的全站禁令或永久偏好。
