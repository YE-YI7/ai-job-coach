# 改稿内部黑盒：用户面撤掉HR及处理报告，保留真实导师沟通

## 本人反馈与范围

2026-11-14本人明确：“不要给用户这个东西，改简历是我们自己的内部黑盒”，并问8次访谈改成8位销售后，导师有无主动指出，以及当前成稿总体质量。

本轮落实用户展示边界，兼做既有Trace零费回查，不同时调作者/HR/工具/知识/Memory，不增加模型调用，不把隐藏报告当漏提醒修复。旧作答、原稿、建议状态、钱包和积分不写；内部HR与Trace数据保留。

## 界面实施

- 简历正文区撤掉原始HR点评入口；移除无其他调用的HR展示组件、样式和对应旧展示测试。
- 右侧导师不再渲染内部处理回执、原始summary/选材说明、原始HR报告；删除无调用的处理回执组件。
- 实际页面验收又发现高亮弹窗暴露“F6作者交付／宿主生成原位差异”的内部reason，当前与旧版工作台均撤掉原始reason展示；真正需要用户核对的事实提示继续保留。第一份待发UI构建未切正式，补齐该展示面后重新核验发布，不把部分入口清理当全部完成。
- 保留实际导师guidance、已有聊天/答案、逐步回复、模型选择、确认/拒绝、未完成/失败告知、付费确认、保存和导出。只把确认弹窗和模型选择提示里的内部质检描述改为用户能直接理解的动作。
- 未删HR调用、事实与身份保护、后台证据或存储字段。API仍保存原记录，非清数据、CSS藏字或换一套Harness。`CockpitApp.tsx`只删该组件的import与挂载两行，没有整文件重构。

## 8次访谈坏例的实际证据

本轮回查`c1e170dd-7eb2-4b3b-a161-1e88cf44d33e`原始spans与已保存任务，没有新模型请求：

1. 原稿是“我参加了8次销售访谈”。首稿写入节点`c59e9300-ad23-43ee-a83c-076cd216e143`已变成“访谈8位销售”。
2. 招聘HR复述了8位；它按既定职责只看新稿，未拿原稿核源，不能把它当口径已经核对的证据，也不因此擅改HR职责为全面审计。
3. HR后写入节点`64e223af-e7f9-44dc-ba6f-aa4f5e5267ba`仍保留8位。首稿/末稿的两条导师消息都只问转人工和120题来源，没有提次数与人数差别。
4. 作者notes也只列转人工提出方/阈值、120题来源的未知项；没有识别该计数单位变化。故这是作者改写及交稿自查/导师告知的遗漏，不是用户没看见、UI没显示，也不是HR后才引入。

已留原稿片段、两条导师原话、节点ID及逐阶段布尔结果于私有`forensics.json`。只确定首次出现与传播路径，未通过单变量实验证明某一句Prompt是唯一根因；本轮不靠再叠提醒或加解析器冒称已修好。漏提醒仍是待修的Harness质量缺陷，当前界面撤入口不掩盖它。

## 替用户读稿的结论

比只改错字强：版本混用的定位、把答不准拆成验收项、固定120题验证、放弃智能问答和取消率诊断，均能体现AI产品实习生的判断与验证。

仍不够成熟：实习4条/项目3条，长背景＋技术过程与验证拆条，关键能力被重复说明冲淡；保留了较泛的个人评价。净正文891→936（+45，约5.1%），不把Markdown原始922→1081误报成正文增17%。主要问题是信息密度与主次，而非单看字数。另有HR后“据此提出”比原稿“一起改”增加提出者归因。没有JD，不能承诺能过某家公司的初筛；HR建议约面不是独立质量认证。
