## 六、第二轮复查三处上线阻断修复（2026-09-21）

第二轮复查确认 650 用例全过，但指出三处上线阻断：拖拽丢内容、导出可能仍是旧顺序、确认状态≠保存成功。本轮补的测试全部断言**数据不变量**（每行都在、失败回滚、导出恒等于当前正文），不再只看界面顺序。

### F1 拖拽丢简历内容（复现行：「技能：Python」拖动后消失）
- 根因两条：`classifyHeader` 把「技能：Python」这类冒号后带内容的短行误判为章节标题（内容被当作空节丢弃）；任何「有标题、无正文」的节在 `flush` 提前 return，标题行不进任何块，重建时消失。
- 修复：`lib/opportunities/resume-blocks.ts` 冒号守卫（`分类标题` 冒号后仍有文字则不是标题）+ 悬空标题独立成块（`flush` 空节也保留标题行）。
- 测试（round-trip 不变量）：`resume-blocks.test.ts` 新增「重排不丢内容」describe——含「技能：Python」尾行的简历，split 后该行必须存在于某块；拖动项目块后**逐行**断言原文每个非空行仍在新 `resumeText` 中；末尾孤零零标题、连续标题无内容均不丢。
- 浏览器复现（demo mock 注入 GPT 原场景简历）：拖「数据看板」到「智能客服工作台」前，顺序真实改写且页面全文包含全部 8 个原文行，「技能：Python」不再消失。

### F2 冻结后拖拽，PDF 仍读旧产物
- `Opportunity` 新增 `frozenStale` 标记：`applyReorderToOpportunity`（拖拽统一入口）在已有冻结产物（`applicationQuality.artifactId`）时改写正文的同时置 `frozenStale:true`。
- 三处消费：`resumeProgress` 把 stale 视为「检查未通过」，动作强制回 `check`→`freeze`（提示语明确「旧投递版本已过期」），已冻结版本号不回退；`ResumeExport` 在 stale 时**不传 artifactId**，导出一律用当前正文（宁可不导旧版，不再出现界面新序/PDF 旧序）；重新冻结成功时清除 `frozenStale`。导出标签同步显示「投递版本 V2（已过期：正文在冻结后又改过）」。
- 测试：`resume-progress.test.ts` 新增 stale 用例（action=check、steps=[done,active,waiting]、hint 含「已过期」、frozenVersion 仍为 2；恢复后回到 export）；`resume-blocks.test.ts` 新增 `applyReorderToOpportunity` 三分支（有产物→置 stale、无产物→不置、no-op/未知 id→changed:false）。
- 复验边界：冻结→拖拽→导出的端到端链路需登录态与质检产物，demo 无法人工走通，由上述 jest 覆盖；拖拽触发 `frozenStale` 的 UI 播报文案已在 demo 拖拽中核对。

### F3 确认状态不等于保存成功
- 新增纯函数 `lib/opportunities/stage-save.ts::commitStage`：live 模式下 **PATCH 返回 ok 才提交新阶段**，失败（含 500、非 JSON、网络异常）时返回**原列表**（引用相等，界面回滚）+ 错误原因。
- 确认条按钮改为 `await` 保存结果：成功才关闭确认条并记日志；失败时确认条保留可重试、按钮期间「正在保存…」，announce 明确播报「状态没有保存：<原因>——岗位仍是「旧状态」」。
- 测试：`stage-save.test.ts` 5 用例——成功提交（断言 PATCH 收到含新状态的整份岗位）/ `{ok:false}` 500 → 列表引用回滚 / 抛异常 → 回滚+「网络异常」/ demo 本地直接生效不发请求 / 岗位不存在不误提交。
- 复验边界：真实 500 回滚在 demo 无法人工触发（需登录），由 jest 断言回滚引用相等覆盖。

## 七、Codex 收口修复与发布门禁（2026-09-21）

## 八、用户第三轮实测四处整改（2026-09-21）

用户实测反馈四个问题：markdown 简历整篇一块没按节拆开、渲染露出 `**`/`##` 符号、模拟面试台仍挂「下一题练什么」堆料、开始模拟面试报「DeepSeek chat 模型不可用」、右侧对话看不见用户在左侧做了什么。对应四处修复如下。

### M1 markdown 简历分块失效（「怎么是一整个简历一块儿」）
- 根因：`classifyHeader` 只认裸文本标题，`## **实习经历**` 这类带结构符的行识别不出，全文落成一个 `other` 块。
- 修复：`lib/opportunities/resume-blocks.ts` 新增导出 `stripResumeMarkdown`（剥 `#`、列表符、`**`/`__`/反引号），标题识别与条目判定先剥离再匹配；节内按空行**或条目开场行**（含日期或以加粗行开头）拆卡，卡片标题用剥掉日期/结构符后的条目名。
- 渲染：`ResumeWorkbench.tsx` 显示层新增 markdown-lite（`**加粗**` 渲染为 `<strong>`、结构符剥离），**仅显示层**——`resumeText` 字节不动，round-trip 不变量仍成立。
- 测试：`resume-blocks.test.ts` 新增 describe「markdown 简历也能按节/条目分块」4 用例（实习 2 卡 + 项目 1 卡各自独立、round-trip 逐行不丢、拖动后逐行不丢、change.section 兜底落回正确卡片）。
- 浏览器实测（preview 注入 `# / ## / **` 简历建岗）：出现「基本信息 / 字节跳动 · AI 产品实习生 / 美团 · 产品实习生 / 数据看板重构 / 教育经历」独立卡，页面全文无裸 `**`、无 `## `；把美团拖到字节前，全部原文行仍在。
- 自查补刀（同日复查发现）：旧拆卡规则要求「前一开场行不是日期」才拆，LLM 紧凑简历里**条目间没有空行**时（`**字节跳动**\n主导…\n**美团**\n搭建…`）两段实习仍并成一张卡；且反向缺陷——非日期开场后任何**句中带年份**的描述行（「接手于 2022 年的老系统…」）会被误劈成新卡。新增 `isStrongEntryOpener`（加粗行首或日期行首才算新条目），卡片在已有正文行后才允许被强开场行拆走，公司行与自己的日期行不拆散。测试 +3（紧凑加粗条目无空行拆两卡、纯文本相邻日期行拆两卡、句中带年份不误劈）；浏览器实测紧凑简历：字节/美团各自成卡、「2022.01-2022.06 接手于 2021 年…」留在项目卡内不劈开、拖动后逐行不丢、无裸 markdown。
