# 首次辅导与改稿恢复（2026-10-08）

## 用户问题与范围

初次求职用户已上传简历、选方向、找岗并分析候选，普通每日 3 次 chat 额度被前置任务耗尽，第一次求教即 403。简历改写被事实守卫拦下时，仅提示补充完整经历，用户不知道下一步该填什么。

本次修复两处断点，不重做工作台、不放松事实守卫、不改付费价格、不承诺一次就能生成可用改稿。失败时保留原文和退款也是有效反馈，但必须提供可执行下一步。

## 产品规则

1. 每个尚无已保存导师回复的账号，有一次独立首次导师保障。正常额度优先；耗尽时仅 `cockpit_agent` 的 chat 请求可以领取。导入、找岗不能领取。成功永久用掉，失败可重试；并发唯一预留，不通过定时过期释放绕过限制。崩溃留下的 reserved 需要核对实际回复后人工恢复。
2. 成本上限为每账号额外一次现有导师请求，仍受现有模型输出限制；不新增搜索/模型扇出。TokenPay 与付费额度规则不变，不把免费次数标成实际人民币成本。
3. 422 无可用改稿：保留原文、返还改稿次数，在简历旁引述原文一段并只问一个本人动作/交付问题；无可引用经历则问一个真实项目起点。不要求凑数字。
4. 用户点“保存补充并继续改”：先保存用户自述材料，标记待核实，再将刚保存的完整材料传入原改稿链；不为保存另跑分析或扣 chat。保存失败保留输入。改写建议仍需逐条决定，不自动采用、不自动确认事实。
5. 已有拖拽、自行编辑、保留原文、预览/PDF 均保留；补充后旧检查/冻结版过期，当前正文仍可导出。

## 验收

- 正常 chat 耗尽后首次导师真实回复可落库，第二次无额度请求被拒；失败退款、并发仅一次，普通账号不可直接调用保障 RPC。
- 无建议 422 返回明确恢复问题、退款且零伪产物；补充保存后读回完全一致、无原文丢失，重新改稿读更新后的内容。
- 桌面/手机问题和按钮可读；保存失败输入不丢；原文预览/PDF 仍可使用。
- 发布以隔离干净构建、实际模型请求和数据库读回为准。合成新手测试不代表真实用户留存或访谈。
