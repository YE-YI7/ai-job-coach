# 导师回复展示合同

用户在2026-10-20再次指出：不能因为新开聊天入口就丢失过去的展示规则。第三点已澄清为“对，要逐步显示回复”。此文件与 DESIGN.md、resume-inline-review surface 共同约束后续入口，不是新的整站视觉方案。

## 必须保留

1. 导师正文统一通过 `TutorMarkdown` 渲染。粗体、段落、小标题、引用和列表是实际的语义元素，不把 `**`、JSON 或内部编辑字段当作正文显示。用户原话仍按纯文本展示，不把用户输入变成可执行 HTML。
2. 正文继承同一无衬线字体、字号和墨色；小标题与重点靠600字重、段落和列表间距区分，不重新引入大标题、多套字形、多色状态墙或嵌套卡片。列表显式保留圆点/序号，不能被全局样式清掉。
3. 新简历讨论使用既有一次模型调用的实际 `reply` 前缀逐步呈现。不用定时打字制造假流式，不向用户发送思考、JSON、editorBrief 或补充引用字段；尚未闭合的格式标记等到可渲染再展示。
4. 流式正文是生成中的回复，不是保存回执。完整 JSON 校验、原任务所有权/版本检查、原保存及计费路径仍走完，才发送最终 done；只有导师有效 revise 决策才能调用原编辑。失败不显示“已保存”，原消息仍能用相同 ID 重试，无自动多次计费或模型切换。
5. 新发送只定位一次到该轮顶部，并留阅读空间。后续 token、轮询和最终替换不抢滚动；用户回看旧消息不被拉回底部。完整结果替换临时前缀，不能追加一遍造成重复。
6. 发送即清空匹配草稿；失败仅在输入仍空时恢复它。生成时可准备下一条，但不能并发发送。重试历史消息不清掉另一条未发送内容；切换岗位/任务不把流片段串到另一处。
7. 旧对话和新入口共用渲染组件；刷新恢复已保存原文时不重演打字，也不重跑模型。左导航、原纸面、模型选择器位置及已有气泡不在此次重设计范围。
8. 手机正文16px，发送44px；减少动态效果关闭等待点的明暗变化，不阻止真实正文到达。输入保留白色书写面及既有柔影，不新增彩色/灰色外框。

## 防回归入口

- `components/cockpit/resume-conversation.test.ts`：防止新入口退回 raw paragraph、未接流读取或按token滚动；保模型入口与稳定请求编号。
- `lib/coach-harness/tutor-format.test.ts`：格式不改变原文字词；分段遇到不完整强调时不闪裸星号。
- `lib/coach-harness/resume-reply-stream.test.ts`：每个JSON切分点、转义和Unicode、内部字段不外泄、先文本后保存、最终不重复、取消不重复执行。
- `lib/coach-harness/resume-conversation.test.ts` 与 `app/api/coach/resume-agent/route.test.ts`：真实控制器接线，流式不绕过原校验和编辑边界。
- 浏览器必须分开记录：渐进中间态、最终排版、手动回看、不同草稿、中断恢复/同ID重试、刷新和新开讨论。模拟延迟流不冒充真实收费模型或云端业务写入验收。
