# Eval / Trace 竖屏动线：实现与边界

## 本人提出的问题与本轮决定

面板原本为减少口头来回而建，却更新不及时、难读，最后仍靠聊天解释。本人要侧面打开、适合竖屏、用图形动线抓要点，不默认铺开细碎输入输出和代码。复核品味原始记录 Round 31/32：10 月 30 日已提出同类问题；旧实现有调用树/动线但三栏文字占满，并未解决窄屏阅读。本轮不再把测试通过冒充可读性验收。

实现为既有 Eval Lab 的新阅读入口，不替换 Harness，也不重跑模型。先显示本轮问题，再沿实际输入→作者→所选工具→HR→返修→结果阅读。工具归到调用它的作者节点内，点开可看实际返回及独立的正文、notes、导师说明。人工定位明确标来源，额外 Judge 不混进作者链；没有记录的选择理由不补写，不把工具读取等同正文采用。

## 已确认原因与接线

- 原 `public/eval-lab/app.mjs:refresh` 保留 URL / 已选 ID / sessionStorage 旧选择，只手动刷新。这保护了历史阅读，但没有明显提示存在新运行，不能保证本人在看最新；不是后端缓存已被证明失效。
- 原 `trace-flow` 将动线、证据和评估分成三栏；每步仍带多段说明，不适合侧面窄屏。
- 新 `/admin/evals/trace` 保留管理员鉴权，用现有同源 `/api/admin/eval-runs`，不新建数据表或变更 RLS。
- 新视图初次无指定 ID 时按时间选最新；指定历史 ID 则固定，列表出现更新时明确给“有新运行，查看最新”，不悄悄切换。
- 每 15 秒在可见页面核对列表与选中详情；窗口恢复可见/聚焦也刷新。`no-store`，核对时间可见；刷新失败保留旧内容并标更新失败/上次成功时间；切换运行先清旧正文，晚回请求不能覆盖新选择。
- 修改了旧面板一个“竖屏动线”入口，随当前运行 ID 跳转；未改旧实验结论。
