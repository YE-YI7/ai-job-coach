# 导师阅读空间、流式回复与发送状态修复

## 确认原因

- AgentConversation 每次 turns / pending / busy / draft 更新都设 scrollTop=scrollHeight，生成中持续抢走阅读位置。
- 输入在成功返回后才清空，而非发送时清空。
- 服务端订阅模型流但只发进度提示，正文一直等全部生成和最终守卫完成；因此不是用户可见的实时回复。
- 顶部多行固定信息、外栏留白和大输入框压缩阅读区。

## 修复

- 右栏按剩余高度分配，紧凑标题/单行岗位与历史；练习邀请进入滚动正文；两行输入按内容增高至 112px，收窄底部说明。
- 每次发送仅定位一次到新回答顶部，并预留阅读空间。分段到达/最终保存不再滚动；手动回看不被抢回。
- 发送即清空匹配的输入；失败在未填写下一条时恢复原问题，已写的下一条不被覆盖。
- 普通教学采用 answer envelope，完整句段经现有断言守卫后以 replace 快照发送。最终核对替换而不是追加，不复制流式前缀。blocking/未遵循协议的旧回复及简历 JSON 仍缓冲到最终核对。最终保存失败仍可见，不冒充已保存。
- 主动开课请求 ID 使用已消费集合，避免 A/B/A 重放。模型连续三段长文本完全重复时中止，失败不写成功产物、不自动换模型重试。此防护不宣称涵盖所有语义重复；未取得用户那次循环的原始 trace，不能断言其唯一原因。

## 验证及边界

- 95 套件 / 811 用例通过，变更代码 ESLint、TypeScript 和 production build 通过。
- 新增流式到达早于模型完成/写库、最终不重复、blocking 不外泄、长段重复中止回归用例。
- 本地临时组件夹具使用真实 AgentConversation、8 段延迟 NDJSON：发送立即空输入，完成后 scrollTop 保持 1367、第一段与阅读区顶部对齐；手动滚到 100 后完成仍为 100；下一条草稿保留。
- 390px 无横向溢出，夹具阅读区 530px、输入区 117px。实际 cockpit 1280×800 阅读区 460px、面板 675px；截图已查看。
- 夹具源文件与对应失效生成类型已移除，不部署测试接口。首次 build 因已删夹具的残余 Next 类型失败，清理后重跑成功。
- Impeccable 收尾手动检测只报历史面试边框两处、Georgia 声明一处，未扩修、未开启自动 hook。
- 本轮是浏览器延迟流夹具及服务端回归验证，不是真人 TokenPay 付费模型速度评测；实际首句速度仍取决于模型与网络。
