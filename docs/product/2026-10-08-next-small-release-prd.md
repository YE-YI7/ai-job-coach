# 益职 AI 下一小版本 PRD：选得明白，练出成果

日期：2026-10-08。状态：需求设计，可进入开发拆分；尚未实施、未代表上线能力。

本稿是既有「任务内学习与 Agent Harness PRD」的增量，不替换完整求职范围，不删除简历编辑、拖拽、模板、导出、面试、复盘、谈薪、笔记与多岗位历史。当前代码基线：`38fd5e1`，实际部署与实测见 [本人账号复验](2026-10-08-owner-account-user-journey.md)。

## 1. 版本决策

**本版只解决两个问题：用户不知道推荐岗位为什么值得选；用户聊完不知道自己具体获得了什么。**

交付两个闭环：

1. 简历与方向 → 少量候选 → 看懂适配依据和风险 → 自己决定推进哪一岗。
2. 当前困难 → 针对性辅导 → 用户实际尝试 → 具体反馈 → 可编辑、可找回的成果。

界面围绕这两个闭环收敛；Harness 围绕证据、任务承接与可靠保存收敛。不是重新做一个聊天产品，也不是把所有求职阶段重新设计一遍。

不以报告长度、聊天次数、匹配分、Agent 数量或测试数量证明产品好用。长期目标仍是帮助用户推进符合自己目标的求职；本版不承诺录用。

## 2. 依据：哪些是真实问题，哪些还只是判断

| 证据 | 已知事实 | 可支持的判断 | 不能推出什么 |
| --- | --- | --- | --- |
| 本会话多轮用户转述的外部反馈 | 找不到入口、功能复杂、建议“已采用”却无法继续、导出不可用、老师没有主动带学 | 操作状态与用户目标脱节，需要让主动作和结果可见 | 反馈人数、问题发生率与付费意愿未知 |
| 10-04 后台只读核验，记录在业务日志 | 近七天活跃账号 2、导师保存回复 21；导入开始 9、成功 2、失败 7，失败为 422 | 当时首次材料处理是明确阻断；不能只优化拉新 | 内部账号未完整排除；该时段不等于今天数据，不能算外部留存或最新故障率 |
| 10-08 合成用户旅程 | 初级方向出现高级经理；补充后仍无改稿；首答后额度阻断；笔记被挤没 | 当时选岗、改稿、教学、笔记存在真实路径缺陷 | 后续已修，不能继续写成当前都未修；见 [修复记录](2026-10-08-user-journey-blockers-fixed.md) |
| 10-08 本人账号正常使用 | 四轮教学能接续、三轮刷新回读；五条国内候选来自腾讯/字节/欢句；技术表述有过度概括，多个候选重复引用宽泛经历 | 功能可用不等于判断可信；推荐与教学内容质量应成为下一版重点 | 一个人自测不代表外部用户满意，生成吞吐不等于首字延迟 |
| 本稿用户心理推演 | 可能怕简历被改坏、怕白花时间、怕老师说得对但自己做不出 | 用可撤销修改、原文依据、具体成果降低风险 | 这是设计假设，不是已完成访谈 |

问题链：用户进入产品是为了做决定或完成事情 → 当前部分输出停在“信息/建议” → 用户还得自己理解内部状态、判断内容可信度、组织下一步 → 产品把工作还给了用户。下一版减少这部分负担，而非增加功能墙。

## 3. 竞品分析：借交付机制，不借未经验证的承诺

### 3.1 FResume：国内直接竞品

正确入口是 [fresume.odsy.com.cn](https://fresume.odsy.com.cn/)，不是面向美国的同名 fresume.com。本轮公开页只能读到邮箱登录；没有新做登录内体验。以下区分作者资料与 09-28 历史亲测。

[作者在 TRAE 社区的说明](https://forum.trae.cn/t/topic/174801)将简历区域修改、岗位定制、面试指南和网申包连在一起，重点是从已有文档快速交付。历史亲测跑了建档、方向推荐、经历生成及部分入口；Word 下载、Focus/Fit 与插件未完成验收。历史路径出现未提供奖项被写入经历、无照片无法继续，不能泛化为其所有功能一直如此。证据真源：`/Users/yi/me/益职作战盘/FResume竞品实测-2026-09-28.md`。

借鉴：一段内容的修改与采用、预览、导出紧邻；已有资料复用。避免：凭空生成经历、前置步骤拦住首个成果、把作者曝光和 offer 自述当成产品效果。

### 3.2 Teal：材料与目标岗位连接

官方 Job Matcher 支持从已收藏岗位、搜索岗位或手动 JD 进入；缺失/已有关键词可悬停定位简历、忽略或生成候选表达，用户再选择采用。[官方使用说明](https://help.tealhq.com/en/articles/12060992-using-the-job-matcher)

借鉴：已有岗位不必重贴 JD；建议可回到具体原文和修改位置。避免：把关键词命中等同于能力、国内录用概率或真实资格。

### 3.3 Jobscan：问题、修改与再次核对闭环

官方扫描器将简历/JD 比较落成关键词、内容与排版检查；说明其 match rate 是自有可视化指标，而非实际招聘系统给应聘者的分数。[官方说明](https://www.jobscan.co/resume-scanner)

借鉴：每个缺口指向可执行的修改，再核对当前版本。避免：照搬 ATS 适用范围、75 分门槛或访谈提升宣传；本版不做伪精确匹配分。

### 3.4 Yoodli：练习后有可回看反馈

官方文档把面试角色/公司、动态追问、View Analysis 与保存联系起来，用户可选择继续练习。[官方练习说明](https://support.yoodli.ai/en/articles/9550465-practice-with-yoodli)

借鉴：练习结束有明确交付和继续/结束选择。避免：把说话流畅或自动评分当能力认证；本版不因此加实时语音模型或录屏。

### 3.5 对标结论

Teal、Jobscan、Yoodli 本轮仅核验官方公开说明，未登录体验；不声称当前付费界面或实际效果已经验过。FResume 有历史登录证据但可能已变化。没有竞品利润与外部留存证据，不用这些猜测做版本优先级。

益职已有找岗、改稿与导师，不缺入口数量。应把它们串成能被用户核对的交付。**“有来源的岗位取舍 + 可验证的小练习成果”是本版待验证的价值，不是已建立的竞争优势。**

## 4. 用户分析与优先场景

不通过注册时间、学历或旧职称自动认定用户是新手。按当前任务分流。

| 场景 | 用户想完成什么 | 典型顾虑（待访谈验证） | 本版交付 |
| --- | --- | --- | --- |
| 已有简历，但没确定岗位 | 少看一些无关岗位，知道先推进哪个 | 推荐只是爬得到的清单；自己的经历不够 | 至多三条首屏候选，具体依据/资格/风险，保存一个自己的决定 |
| 已选岗位，遇到不会的问题 | 学懂一个机制，能自己答出来 | 老师一直给长解释；学习被转成面试话术 | 一次尝试、针对该尝试的反馈、一份可编辑练习记录 |
| 明天面试，只想快速准备 | 修好当前最重要的回答 | 被要求补课、重复建档、耽误时间 | 用户可直接要草稿/练一题/跳过，保存当前回答，不强制课程 |
| 只想改简历/正在谈薪 | 完成当前任务 | 为了新功能旧功能又不能用 | 保留直达编辑与导出/谈薪；不强迫找岗或学习 |

首批可用性招募：6 名非内部用户，其中 3 名选岗、3 名已有岗位需要练习；覆盖至少一名转岗者、一个非互联网方向和一名手机用户。不另招人时先用合成材料做质量评测，但不能替代真人验收。敏感履历由参与者明确同意后用于任务，不公开、不默认进入训练集。

## 5. P0-A 岗位推荐变成可解释的选择

### A1 输入和约束

- 保存有效简历与方向后沿用已有自动查找；回访优先恢复当前版本的已保存结果，不因打开页面重复收费。
- 已有岗位仍可直接进入，不要求先找岗。没简历也能学习，但不得给“已结合简历”的推荐。
- 方向、地点、用户明确选择的级别/公司偏好/排除项是约束；简历旧职称不是新的求职偏好。
- 一般材料缺失不反复要求补全。只有会改变当前岗位资格/排序的关键未知，才问一个问题；可跳过，相关岗位移到待核实。
- 明确初级且不考虑销售：高级/负责人、销售岗不进入优先清单。领域年限与总工作年限分开；不把实习、重叠任职机械累加。

### A2 首屏与分组

首屏最多三条，按适配证据和已知条件排序，不按大公司名气或来源返回顺序排序。余下最多两条放“更多候选”；已知冲突进入折叠的“暂不合适”。

两个可见状态：

- **值得进一步了解**：无已知资格冲突，有具体经历与职责的对应证据；不等于保证有面试。
- **先核实条件**：领域年限、在读身份、城市冲突等必需资格未知。未知不等于不合格，但不占优先候选位。

零条优先候选允许成立。显示“这次没有找到可优先推进的岗位”，明确是来源失败、供给有限还是已知约束排除；只给一个可选动作（调整一个约束、稍后重试或导入已有 JD），不拿不适合的岗位填数。不得擅自放宽用户排除项。

### A3 每张卡的默认信息

公司标识/简称、岗位、地点、可核验薪资（未知不补）、上述状态。其后只展示：

1. 一条**为什么值得了解**：用户做过什么 → 对应岗位哪项职责；各保留来源引用。
2. 一条**最影响决定的风险**：资格未知/实际差距/招聘信息待核实，分类不能混用。
3. 一项主操作“看看是否值得投”。原招聘页为次操作。主操作复用已有岗位分析/导入流程，不额外做另一遍收费评审。

“依据”展开后左右对照简历与 JD 的连续原文，附来源、抓取时间及当前材料版本。不给每个岗位重复同一句个人总结；相同引文可合理复用，但必须对应不同且明确的 JD 职责，否则降为不足以形成个性化结论。

例（纯交互示例，不是真实用户事实）：

> 用户运营 · 上海
>
> 值得了解：你做过退货原因分类，与该岗“整理用户反馈”相近。
>
> 要先确认：该岗要求独立运营活动，你的材料尚未证明。
>
> [看看是否值得投]　[招聘原页]

### A4 一个自己的决定

已有分析页面顶部保留“我会先推进 / 暂不考虑 / 先核实”，用户可选一个原因或自己写，不强迫填表。保存岗位 ID、推荐批次、材料版本、决定与理由；可修改。只有用户选择“推进”才进入工作台，状态仍是准备，不自动标记已投递。

拒绝某岗可用于当前批次排除；不把“这次不考虑”直接提升为永久职业偏好。明确说“以后不要推荐销售”才提出可确认的长期偏好。

## 6. P0-B 导师带到一个成果，而不是一直追问

### B1 首先尊重用户要做的事

三种 intent：学懂、练回答、改材料。优先读取当前明确要求，沿用本会话目标；用户改目标则保留原草稿并切换，不自动退求职阶段。一般继续发问不必让用户点击模式按钮。

每次辅导有一个目标和一个可检验的完成标准。例：“能独立说明为什么追问 Agent 需要考察目标”，不是“掌握多 Agent”。普通咨询不强制建立课程、做题或产物。

### B2 最小辅导闭环

针对当前缺口给必要解释 → 一个标明示例的小案例 → 邀请用户尝试 → 引用用户具体回答反馈。

- 回答已覆盖标准：说清覆盖了什么，提供“结束这次 / 再练一个”的选择；不自动编新缺口维持聊天。
- 只覆盖部分：指出一个关键缺口，给提示并让用户重试；不重新倾倒开头讲解。
- 用户仅说“懂了”：可以保存笔记，但只记录“读过/未独立检验”，不宣称完成独立练习。
- 用户说“没做过”：可教概念或做个人实验，不把简历中的相似项目强行说成其已经做过。
- 读取失败：显示材料暂不可用并重试，不判能力不足。

首批质量打磨三个窄场景：经历表达、RAG 评估口径、Agent 任务分工与上下文边界。其他问题继续正常对话，但没有经过专项评测就不展示“已达标”的能力状态。原 PRD 十二单元路线仍保留，本版不假装全部补齐。

### B3 成果卡：用户能修改和带走

在用户完成一次有效尝试或明确要求整理时，聊天末尾给一张紧凑成果草稿，不能固定占据输入区：

- 本次目标。
- 用户当前答案/修改稿，引用对应回答或材料版本。
- 已观察的表现与一个未解决点；没有用户尝试时不生成表现判断。
- 一个下一步，可为“本轮目标已覆盖，是否再练”而不是必有作业。

操作“编辑 / 保存到我的笔记 / 复制”。用户可只保存自己的答案；普通复制不收费。保存、编辑、预览、回读均不额外调用模型。默认不归档、不锁死对话；保留既有“整理并结束”作为可选操作并清楚说明是否收费。

状态必须区分“草稿 / 正在保存 / 已保存 / 保存失败”。已保存给真实 ID 和找回入口；失败保留草稿与重试；刷新后能回到同一份成果。用户手写修改是新的内容版本，但不自动升级为新的能力证据。

成果示例（教学演示）：

> 本次练习：说明考察目标如何传给追问 Agent
>
> 我的答案：出题 Agent 同时输出题目与目标……
>
> 本次表现：提示下解释了输入边界；尚未观察独立迁移。
>
> 下次可练：换一个客服场景，自己设计输入字段。
>
> [编辑] [存到我的笔记] [复制]

### B4 内容可信度

来源用于关键知识判断，不要求每句话挂脚注。技术定理、数字、协议特性等需要受审核知识条目支持；区分“某种架构下可能这样”与普遍事实。比如 Agent 数量增长不直接推出信息量平方增长；冲突处理也不必只能发生在汇总层。

来源不支持时缩小结论或说明未知，不能编链接。练习示例与用户经历严格分开。模型回答不能被下一轮当成已确认个人事实；用户纠正后保留修正引用，相关旧摘要失效。

## 7. P0-C 只做必要的 UI 收敛

不新增一级导航，不重做六个平行首页，沿用当前三栏。

| 区域 | 本版显示 | 收起/避免 |
| --- | --- | --- |
| 左侧 | 可点击的基础档案、已有岗位、添加岗位；选中与悬停明确 | 不加匹配百分比、不把多个功能伪装成同质 tab |
| 中间 | 当前任务的一项主操作；候选最多三条；已有简历/阶段资产继续可用 | 不重复解释按钮用途，不暴露内部 run/预算/冻结术语让用户决策 |
| 右侧 | 当前目标一行、正文、底部输入；结果卡在相应回答后 | 不常驻旧练习邀请、不固定成果面板挤阅读区、不显示未渲染 Markdown |
| 我的笔记 | 已保存成果优先可见、用户可新增/编辑；待确认事实另行折叠 | 不把原始事实确认队列与用户学习笔记混成一长列 |
| 手机 | 当前任务与导师可切换，切换保留输入、草稿和阅读位置 | 不横向硬挤三栏，不要求找隐藏返回按钮 |

约束：无内层方形输入边框/浅橙描边，焦点改为中性可见状态而非取消键盘焦点；正文至少 16px，主要点击区至少 44px。每屏任务区最多一个强调色主操作，其他动作仍可发现。简历保存/预览/PDF 不因 AI 检查未完成被禁用。拖拽提供点阵手柄、首次轻提示及键盘排序替代，保留原文内容。

默认新回答定位到消息顶部；用户阅读旧内容时不抢滚动。流式等待立即清空已发送输入，失败可恢复问题，不覆盖期间新写的草稿。复杂回复允许充分展开，不靠固定字数切断答案。

## 8. Harness 与存储增量

### 8.1 复用现有链路，先改质量契约

| 工作包 | 现有落点 | 增量 |
| --- | --- | --- |
| 岗位召回/硬筛/私有评审 | `/api/coach/jobs/discover`；`lib/jobs/{open-search,retrieval-gate,verification-gate,personalization}.ts` | 结构化依据与资格分组、至多三条首屏、同批重排和个人决定；不新增搜索器宇宙 |
| 导师上下文与策略 | `/api/coach/agent`；`lib/coach-harness/{context,learning-memory,coaching-strategy}.ts` | 当前 intent/目标/标准/最近尝试优先，反馈引用具体用户回答，终止与换目标明确 |
| 结果保存 | `coach_agent_turns`、`coach_learning_sessions`、现有笔记接口 | 成果独立版本、来源和乐观锁；保存不强制归档；与现有笔记列表接通 |
| 教学知识 | `knowledge-base/manifest.json`、审核 Markdown、编译索引 | 三个场景的标准/反例/独立练习，公开来源支撑；原始来源不直接作结论 |
| 故障/费用/过程 | 现有 run ledger、request telemetry、quota/TokenPay | 统一关联 requestId，区分结果有效/保存成功，真实 token/费用与首字时间 |

本表是开发落点，不代表增量已经存在。`reasons: string[]` 已有引用核验，不再另加一套相同评审；当前通用 prompt 已有短讲/练习/事实约束，但真实内容仍可能失败，不能把“加一句提示词”当完成。

### 8.2 新输出契约

岗位评审输出结构字段而非拼接长文：jobId、eligibility（pass/unknown/conflict）、requirementRefs、resumeRefs、fitReason、decisionRisk、nextAction。模型只能选本轮候选和来源 ID；服务端回填原文，校验资格分组与引用。引用存在只是必要条件；引用与职责的语义关联仍进入质量评测。

学习成果：sessionId、goal、criterionVersion、attemptTurnIds、answerDraft、observedStatus、evidenceRefs、openIssue、nextStep、revision、status。observedStatus 只允许“未独立检验 / 提示下完成 / 本题独立完成过”，是本题表现不是永久能力认证。

草稿沿用一次导师调用产出；流式正文保留现有协议，结构化成果作为独立的最终事件，在引用/schema 校验后才能展示为可保存草稿。校验不通过不展示成果卡，正文和原回答仍保留，并说明本次未形成可保存成果。保存事务返回真实 ID 后才显示成功。

字段及数据库迁移在开发前以现有表结构为准：优先给现有学习/笔记持久化扩展 typed payload，不把 JSON 拼进 summary 字符串。若现有表无法保存独立成果和 revision，才加 owner 隔离的成果记录及编辑接口；旧学习摘要保持可读，不批量重写用户笔记。

### 8.3 每次上下文、缓存与 memory 的边界

1. 验证用户和任务作用域；读取当前选中 JD/简历版本，不能只取“最近几个窗口”代替任务检索。
2. 读取本会话目标、用户最近尝试与未解决点；按需要检索同岗位或用户确认可复用的历史成果。只展示相关摘要，来源仍可回查。
3. 公共知识按 intent 与具体问题召回。硬事实原文和当前纠正优先，不因压缩丢掉；超过预算则缩小任务，不偷偷截断后作强结论。
4. 公共招聘抓取缓存不含个人履历。私有推荐 key 包含 owner、档案版本/指纹、方向/约束、召回与评审版本；资料变化失效，但保留旧批次可查看。
5. 本轮短期对话在 context；原始 turn 在数据库。长期背景及学习文件目录仍是数据库中的逻辑路径（如 `profile/overview.md`、`learning/<id>.md`），不是声称每个用户已有本机文件夹。
6. 成果保存时保留答案、反馈、提示依赖与来源；不要将模型示范直接写进确认事实。新会话检索已保存成果和未解决点，不全量塞历史聊天。
7. 用户编辑/删除来源、纠正背景时，相应摘要与私有缓存失效；不复活被删除的来源。保存须 owner 过滤、revision 乐观锁、requestId 幂等，409 不吞错覆盖。

本版不新增每用户常驻沙箱：笔记、简历和对话档案用现有数据库即可。真实代码项目执行再沿用按任务临时沙箱，单独授权/隔离/回收；不能把“有目录”当沙箱安全或能力证明。

### 8.4 费用、失败与主动性

- 正常搜索维持当前最多 7 次来源外呼、1 次私有模型评审；不为了三张卡各调用模型。推荐展示与保存不追加模型调用。
- 不增加每轮隐形规划/模型复核，质量评审先离线做。线上保存草稿、读笔记、展开依据、回访恢复不收费；生成收费沿用现有规则，新增调用需明示。
- 部分来源失败可展示已验证部分，但不说搜索全部完成。全失败不退回固定大厂清单。模型失败、保存失败、资格未知分开反馈；保留现行失败计费处理，不擅改额度或 TokenPay 计费语义。
- 主动建议只在新目标/实质材料变化/用户明确不会且需另开辅导时触发；正在学习由当前对话承接。忽略后无新证据不重推。心跳既有机制保留，本版不新增邮件、短信或持续抓取支出。

## 9. Evals：上线门与用户效果门分开

### 9.1 必须建立的质量集

总计 40 个主体案例：20 个选岗、20 个多轮教学。另有 10 个安全/失败反例和 8 条真实端到端路径。案例记录模型/prompt/知识/材料版本和脱敏引用，不收私密履历；模型评审不能取代人工。

选岗覆盖：AI PM、转初级运营、非互联网方向、明确排除销售、年限未知、领域年限不同于总年限、只有一条可用结果、空结果、学生身份、公司同质供给。同候选池换用户档案，理由/优先级应随证据变化；相同档案反复采样则检查稳定性，不要求所有人排序不同。

教学覆盖：不会概念、说不清、没做过、材料没取到、纯问问题、已满足标准、改目标、纠正导师、隔夜恢复、要求直接改一句。每条至少三轮；必须含“用户已答对，但导师继续虚构不足”和“用户只读过但被标掌握”反例。

人工每例按 0/1/2 评：建议与目标相关、证据支持、反馈针对实际尝试、下一动作可执行、可用成果。2=成立、1=需修改、0=错误/无效。资格/虚构经历/跨用户泄露为独立硬失败，不能被其他高分抵消。

### 9.2 发布门槛（设计目标，不是已有成绩）

- 10 个安全反例全部通过；40 例中不存在虚构履历、无效引用被标有效、已知资格冲突被列为优先、模型失败伪造评分、跨用户读取、假保存。
- 人工核验至少 36/40 案例的核心建议可直接使用（各项均≥1、关键项目标相关/证据支持=2）；其余只允许清楚显示失败/未知，不允许误导强结论。两位独立标注者审至少 10 例，保留分歧并复核；无人复核时明确缺口，不声称校准完成。
- 8 条端到端全部真实走通；Jest/类型/build 是基础门，不替代这些路径。
- 试点 6 人至少 5 人无需讲解找到当前动作并完成其小任务；保存原始观察与失败原因，不能将 5/6 外推为总体满意率。未招到人可发布受控预览，不签收真人效果。

### 9.3 真实端到端清单

| # | 实际路径 | 通过证据 |
| --- | --- | --- |
| 1 | 保存简历/方向 → 自动找岗 → 看依据 → 确认一岗 | 真实来源和模型；决定保存、刷新可找回；无自动投递 |
| 2 | 两份不同背景 + 同候选池 | 理由对应各自原文；否定项、初级约束与领域年限正确 |

## 10. 指标与取数：不考核我们“自己做了很多”

两个主指标分开，不合成神秘总分：

1. **选岗有效决定**：看到当前版本有效候选的非测试用户中，保存了有具体理由的推进/拒绝/核实决定的人数及比例。拒绝可算有效决定，但需抽样确认理由来自岗位证据，不能只靠点击。
2. **辅导有效成果**：提出明确练习目标的非测试用户中，产生本人实际尝试、针对性反馈，并保存一个经抽样核验可用成果的人数及比例。保存文字不是独立掌握；独立迁移表现另列。

辅助：首次有效成果耗时、重复要求已有材料次数、错误反馈/纠正数、放弃环节、回访恢复成功、实际保存/导出成功、每个有效成果成本。按任务拆分 p50/p90 首字时间和完成时间；tokens/s 单独显示，不能代替等待时间。

新增语义事件建议：`job_decision_saved`、`learning_result_saved`、`learning_result_revised`；后端成功提交时发，不在点击时冒充成功。沿用现有 chat/start/failed/first-token 事件；正式接线前映射实际事件目录，避免同义重复。载荷仅 task/scope/version/status/耗时/费用及关联 ID，不存简历/JD/聊天正文；去重按 requestId 和成果版本。

owner、内部团队、合成账号及其 QA 对话/事件单独排除；未配置内部名单则报告“观察账号”，不能写外部用户。比较前记录新版本与七天基线，每组报 n；样本不足只看具体问题，不作 A/B 因果宣传。

速度目标：读取已保存结果/笔记 p90≤2 秒；导师首字 p90≤12 秒；冷找岗完成 p90≤30 秒。均为待测目标，至少 30 个对应路径样本后报告；当前正常账号只测了吞吐，没有当前首字基线。若超标先定位来源/上下文/模型，不用假进度条或降低证据质量掩盖。

## 11. 实施与发布顺序

| 顺序 | 工作包 | 完成条件 |
| --- | --- | --- |
| 1 | 固化40例与基线，确认结构化结果/保存契约 | 同一批材料可复现当前质量问题，标明已修与仍有缺口 |
| 2 | 岗位卡片与决定保存 | 引用/资格/零结果门成立，首屏至多三条，owner与版本隔离 |
| 3 | 三场景辅导终止标准与成果卡 | 不额外加隐藏调用，保存不结束对话，笔记可编辑回读 |
| 4 | UI收敛和完整回归 | 全部既有功能保留；8条端到端、手动detect一次与必要复核 |

按工作包拆工单，不在缺少人力/工程估算时承诺几天完成。若时间不足，先交付选岗闭环，不另加一个半成品教师面板；辅导仍保持已有正常聊天。

各增量可独立回滚。迁移优先只增兼容字段/记录；回滚 UI 不删除用户成果和原始 turn；不得覆盖其他会话的 auth/admin 改动。发布后核验真实账号正常调用、保存、刷新回读，生产失败则停止扩大试点。

## 12. 明确不做

新一级导航、新课程商城、全市场爬取承诺、浏览器自动投递、实时语音新模型、每用户常驻沙箱、全部十二课程补齐、重做支付/额度、为装饰新增长报告、带录用概率的匹配分、替用户确定职业方向。

既有功能继续维护，不以“不做新增”删除历史能力；本版回归发现直接阻断时必须修复再测，但不因此无限扩大版本。本文不授权自动外发简历、付费或访问其他用户私人材料。

## 13. 尚待验证的产品判断

少量岗位是否真的更容易选；成果卡是否被当成有用资产而非另一张报告；用户是否愿意保存及下次复用；三个场景外的教学覆盖；各行业招聘来源供给。通过试点和证据评测决定下一版，不提前写成优势。

最终验收问题：**用户能否说清“为什么选/不选这岗”，以及“这次我具体改好或练会了什么”，并能找回对应的自己的内容？**
