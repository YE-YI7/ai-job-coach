# 简历优先找岗与主动带学

## 产品决策

不新增「掰岗位 / 掰简历」两套入口。一个个人工作区，一份基础简历，多份岗位版本。首次默认「导入简历 → 确认方向 → 推荐岗位 → 选岗推进」；已有 JD 的人仍可直接贴 JD，在确实需要判断匹配时再补简历。已经面试、谈薪的用户直接进入对应阶段，不重走新手路线。

导入后只请用户确认识别出的方向、城市、年限，采用可修改选项，不再填整套问卷。首次展示 3–5 个可追溯岗位，每项写清推荐依据、主要缺口、来源和核验时间。避免凭模型印象给匹配百分比。选中后进入现有阶段轴。没有简历的人可以从经历梳理或第一项练习开始。

教学不另开工具首页：在当前任务遇到困难时，导师接住困难、解释一个概念、给一个例子、让用户试一次、反馈后重答。练习完成不等于真实工作经历，也不能自动增加能力事实。

## 公司 Logo

可以实现：建立公司实体与已核验官网域名的映射，使用允许展示的官方品牌资源并缓存。记录来源；公司别名、同名企业需消歧。没有可靠图片就显示公司首字，不伪造 Logo、不将任意站点 favicon 当作已核验品牌。属于后续找岗数据接入，本轮没有声称已经覆盖公司库。

## 岗位数据技术路径

1. 首批面向 AI 产品岗位选择企业招聘官网白名单；先确定国内覆盖，再扩展海外 ATS，不能用海外接口数量冒充国内覆盖。
2. 优先公开招聘接口或获得授权的数据源。Greenhouse Job Board 的读取接口与 Ashby 公共 Job Postings API 可按企业招聘板获取岗位，不是全网职位搜索接口。公开可读不自动等于无限再分发授权，接入时逐源核对使用政策。
3. 搜索引擎只负责发现官网详情链接；可访问且允许采集的页面再结构化。LinkedIn 等登录平台不走借用用户 Cookie、验证码绕过或批量爬取路径。保留用户主动粘贴 JD 作为覆盖不足时的入口。
4. 保存 canonical URL、公司、原始职位 ID、标题、地区、描述、发布时间、抓取时间、来源及有效状态。按 URL/职位 ID 去重、内容哈希识别变更。只展示可公开列出的岗位；下架与长期未核验明确标记，发布日期早不能单独等同于失效。
5. 采集在共享后台缓存完成，不给每个用户重复爬。初始刷新间隔 6–24 小时按来源调整；遇到限流退避，遇到登录/验证码停止。规则先过滤地点/级别等硬条件，再让模型对少量候选解释推荐理由。
6. 外部检索仅携带去标识化技能与求职偏好，不发送整份简历和联系方式。抓取服务须限制域名、重定向、响应大小，防 SSRF；网页文字按不可信材料处理，清洗 HTML，不能把页面指令升级为工具权限。

## 主动导师的边界与成本

- 用户明确说「教我」「不会答」：立即将当前题目和原话交给右侧导师，单次请求直接带学，不先运行一次评分再额外跑教学。新辅导保留旧会话，不沿用不相关问题。
- 仅从点评推断出缺口：先给一条带题目的邀请，可稍后处理；不每次刷新都自动计费发言。
- 事件需带岗位与唯一事件 ID，防串岗、防重复；忙时等待，失败显示可重试，不伪造导师已回复。
- 本次上下文保留当前题目、尝试与必要历史；学习结束经用户确认的关键进展写入已有记忆/笔记。未经证明的技能不进入履历事实。
- 验收重心：用户能否完成一次实际尝试并改进，而不是打开过某个功能。评估求教识别误触发、题目/岗位绑定、回复是否循序带学、事实编造率与每次教学成本。

## 本轮已改代码 / 验证边界

- 输入框不再套内层矩形 outline。组合搜索框使用外层圆角焦点，普通文本框保留细底线键盘提示，导师输入区沿用外层焦点提示。
- 导师标题增加现有品牌导师图像，保留文字作为明确身份。
- 单题练习识别明确求教，按钮改为「让导师带我学」，不写评分；将题目和用户原话发送到右侧现有辅导通道。失败提供重试，内部教学提示不塞进用户输入框。
- 本地预览实测「我没搞过这个 教我一下」切换按钮，提交后显示登录边界且不生成评分；搜索框焦点与导师头像已截图检查。真实账户的模型首答和持久化未在本轮验收，不能以预览替代。
- 全量测试 89 套 / 772 项；生产构建结果以发布执行输出为准。
- Impeccable 用于焦点可见性与品牌一致性检查。保留此前用户认可的 Outfit，窄范围登记例外；检测到原有两处彩色侧边与 Georgia 字体未扩大本轮改动。未刷新有漂移提示的设计侧文件，未宣称全站设计审查通过。

后续交付顺序：个人简历档案入口 → 首批国内岗位来源验证及许可 → 候选推荐与用户反馈 → 缺口邀请与教学结果评估。上述找岗与完整新手动线是设计方案，不是本轮已发布功能。
