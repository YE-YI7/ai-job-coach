# AI Job Coach V2 重启路线图

## 1. 重启目标

V2 不继续扩张“全流程求职平台”，而是先验证一个高频、可衡量的核心闭环：

> 上传简历 + 粘贴目标 JD → 获得有证据的匹配诊断 → 生成岗位定制简历 → 针对差距进行面试训练。

首阶段的成功标准不是功能数量，而是用户能否完成整个闭环，并认为结果比通用聊天工具更可信、更可执行。

## 2. 目标用户与核心任务（待需求访谈确认）

首选用户假设：有明确目标岗位、正在集中投递的应届生或 1–3 年经验求职者。

他们的核心任务：

1. 判断自己的经历与某个岗位到底匹不匹配。
2. 在不编造经历的前提下，把简历改得更贴合 JD。
3. 知道面试最可能追问什么，并用自己的真实经历完成演练。

## 3. V2 MVP 范围

### 必须完成

- 支持粘贴文本，以及上传 PDF/DOCX 简历。
- 解析 JD 的职责、硬性要求、加分项和关键词。
- 对每条匹配结论标注来自简历或 JD 的证据；缺失信息明确标记“未知”，禁止自行补全。
- 输出匹配优势、关键差距、修改优先级和风险提示。
- 生成可逐条接受/拒绝的简历修改建议，并保留修改前后对比。
- 基于差距生成面试问题、追问和结构化反馈。
- 保存一次完整任务，允许用户回来继续。
- 对模型输出建立固定样例集和基础评测。

### 暂不进入 MVP

- 成就/积分系统。
- 完整求职投递看板。
- 薪资谈判、Offer 比较等后链路。
- 多 Agent 自主编排和 RAG 知识库。
- 短信登录、团队协作、国内外双部署。
- 面试录音分析（在文本闭环验证后再决定）。

## 4. 产品原则

- **证据优先**：重要判断必须能回指输入材料。
- **不替用户编造**：信息不足时先提问或标记未知。
- **改动可控**：简历修改以差异形式呈现，由用户确认。
- **结果可衡量**：每次分析记录完成率、采用率和用户评分。
- **隐私默认**：简历属于敏感个人数据，日志中不得记录全文或联系方式；支持删除任务数据。

## 5. 技术收敛建议

- 保留 Next.js App Router、React、Tailwind 和现有可复用 UI。
- 首版只选择一种数据库，不同时维护 Supabase/Postgres 两套访问分支。
- 将 LLM 输出改为结构化 schema，并在服务端校验。
- 将“分析、改写、面试训练”组织为普通可观测工作流；验证需要前不引入复杂 Agent。
- 所有密钥只通过服务端环境变量读取；示例文件只能使用占位符。
- CI 至少执行 `npm run lint`、`npm run build` 和后续新增的测试命令。

## 6. 里程碑

### M0：恢复工程基线（当前）

- [x] 建立 V2 分支。
- [x] 清理仓库中的密钥样例。
- [x] 恢复依赖、lint 与 production build 基线。
- [x] 记录 V2 范围和遗留技术债策略。

### M1：需求定稿与评测集（2–3 天）

- 访谈或回看至少 5 个真实求职案例。
- 确定首批用户细分、核心场景和不做清单。
- 收集并脱敏 5–10 组简历/JD，建立人工期望结果。
- 定义核心事件和上线门槛。

### M2：匹配诊断闭环（约 1 周）

- 简历/JD 输入与解析。
- 证据化匹配报告。
- 缺失信息追问。
- 任务保存与恢复。

### M3：定制简历与面试训练（约 1 周）

- 可审核的简历 diff。
- 针对差距的面试题与追问。
- 结构化反馈和下一步训练建议。

### M4：小规模内测（约 1 周）

- 邀请 10 位目标用户完成真实任务。
- 观察端到端完成率、建议采用率和次日回访。
- 根据失败案例调整产品，不按愿望继续加模块。

## 7. 建议指标（需求讨论时定阈值）

- 首次任务完成率：从输入材料到看到诊断报告。
- 闭环完成率：从诊断到至少采纳一条修改或完成一轮训练。
- 建议采用率：用户接受的简历修改数 / 展示的修改数。
- 证据错误率：结论无法由输入支持的比例。
- 用户价值评分：用户对“是否更清楚下一步”的 1–5 分评价。
- 7 日复用率：用户是否针对另一个 JD 再次使用。

## 8. 当前遗留债务

旧 Demo 约 1.4 万行，覆盖范围大于 V2。为建立稳定工程入口，lint 对历史代码中的 `any`、未使用变量和部分旧式 effect 写法做了临时放宽。这不是长期规范：进入 M2 后，触及的模块必须补齐类型和测试，不允许新增同类债务；每完成一个 V2 模块，就缩小豁免范围。

依赖安全告警需要结合实际运行路径逐项升级和验证，禁止直接使用破坏性 `npm audit fix --force`。

## 9. 下一次需求讨论需要回答

1. 第一批用户到底是谁，他们最近一次真实求职卡在哪里？
2. 首个付费/高价值时刻是匹配诊断、简历修改，还是面试训练？
3. 用户愿意提供哪些材料，最担心哪些隐私问题？
4. “好结果”由谁判断，怎样避免模型只是写得更像但事实更差？
5. V2 是个人作品、开源项目、商业产品，还是创业验证？
