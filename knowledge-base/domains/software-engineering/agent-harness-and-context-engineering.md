# Agent 应用的能力栈、上下文供给与可靠性

## 核心知识

依据 Anthropic 公开工程指南与论文，Agent 设计需要同时检查模型调用、材料供给、工具反馈和失败恢复。准备面试时先说明任务和证据，再解释为何需要自主循环；不能把框架名称或调用过 API 当作可靠性证明。

## 模型与工程的边界

1. **先选简单方案**：Anthropic 建议先尝试单次调用、检索和上下文示例，再按效果引入复杂流程。
2. **区分流程与自主性**：固定步骤适合可预测 workflow；开放任务可能需要根据工具结果重新规划。
3. **说清取舍**：自主循环可能提高完成质量，也增加调用成本、延迟和错误累积风险。比较需要同一任务与验收标准。

## 能力栈三层

- **Tool**：模型可调用的执行契约，含名称、描述、参数和失败语义；高风险动作必须保留人工确认。
- **Skill**：流程知识的渐进披露——先元数据索引、触发才加载主体、需要才读附属资源，未使用不占上下文窗口（与 Anthropic 公开 Agent Skills 机制一致）。
- **MCP**：连接 AI 应用与外部系统的开放协议，暴露工具、资源与提示三类原语；「内容稳定就存、实时在变就连」用来判断存快照还是走协议。

## 上下文是有限资源

- **U 形位置偏置**：「Lost in the Middle」论文实证相关信息在长上下文开头或结尾时表现最好、落在中间显著变差。工程对应：关键规则前置、长任务尾部做规约复位、按任务隔离上下文。
- **工程检查**：核对本轮实际装载的证据、材料版本、裁剪范围及引用出处。窗口变大不代表所有位置的证据都能被稳定使用。
- **上下文策略**：按任务选择材料，保留关键决策与未解决问题；摘要不是原始证据，必须能回到来源。

## 评测与选型

- 基准分数不能代替具体任务验收。保留输入、实际材料、模型版本、输出和失败记录，比较正确性、成本与延迟。
- 自动检查适合格式与数据不变量；开放建议的适用性仍需要可解释标准和独立人工复核。

## 可靠性与人机分工

- Anthropic 公开指南建议在沙盒中测试自主 Agent，设置护栏与人工检查点。外发、计费或状态变更等行为应按真实风险配置权限和恢复路径。
- 产品岗与工程岗共用的高频追问：Agent 出错时系统怎么发现、谁能停、怎么恢复。

## Agent 使用方式

准备 Agent 开发或 AI 产品技术面时，用这条链组织真实项目：任务 → 简单方案对照 → 工具契约 → 实际上下文 → 验收 → 失败与恢复。ReAct 提供推理与动作结合的公开研究例子；不能据此声称自己的系统已达到论文结果。

## 边界

本单元仅使用公开官方文档和论文，不纳入非公开培训材料。建议属于工程方法，不能推断某公司的面试流程、必考题或评分结果。
