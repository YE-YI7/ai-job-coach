## 问题和归因

用户要求新开的简历对话也遵守已确认的显示规则：不能显示 Markdown 双星号，内容分段和结构可读，回复逐步显示，保留气泡、单一正文层级、输入留底、模型入口及阅读位置。

本次截图对应的真实导师运行是 `25ccd715-1f93-4199-8769-d859b6ded595`，span 是 `7e9dfea1-707e-498a-b472-ec9a7c1f0540`。其保存输出已有 Markdown 粗体、段落和编号；简历讨论入口却把 `turn.reply` 放进原始 p 标签，没有复用普通导师的渲染器，并在上游完成后才显示整条。该轮是讨论，不存在修改 ID；不能把它关联到上轮超时或两次只读探针，也不补造旧 Trace。

## 修复边界

- 普通导师、简历新消息、历史消息、摘要和提问共享安全 Markdown 渲染。禁用 HTML 与图片，链接安全属性保留；显式恢复被全局样式清除的列表标记。
- 复用同一次模型调用逐步展示根级 `reply` 的可确认前缀，不增加模型调用/自动重试，不做整条生成后的假打字。分片 JSON 转义和不完整 Markdown 不漏出内部结构、编辑计划或半个格式标记。
- 完整输出仍先走原语义校验、租约、计费和编辑判断；流中展示不等于已经执行修改。旧 JSON 客户端继续可用。
- 新一轮只定位一次，后续 token 和最终回执不抢回看位置。发送即时回显，失败恢复原输入，同编号重发不重复，不能清掉用户另写的下一条草稿；历史刷新不重放动画或调用模型。
- 继续使用原气泡、字体和墨色；没有混入共享工作树的首页、纸面、工具栏与其他前端改动。

后续实现须遵循 [导师展示合同](../product/mentor-reply-presentation.md)，对应入口、Markdown/流读取/草稿规则均有回归。不是每开一个窗口重建一套表现。
